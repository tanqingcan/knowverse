# 第3章 SQL 连接查询（讲义）

本讲义为知屿 KNOWVERSE 演示用原创教学资料，用于展示资料引用流程。第 2 版增加了常见错误清单。

## 3.1 连接的含义

连接（JOIN）把两个关系中满足连接条件的元组拼接成新的元组。连接条件通常是两个关系公共属性上的等值比较，例如学生表与选课表通过学号 sid 连接。

## 3.2 内连接

内连接（INNER JOIN）只保留满足连接条件的元组组合。等值连接既可以写成 FROM students s, enrollments e WHERE s.sid = e.sid，也可以写成 JOIN ... ON。没有任何选课记录的学生不会出现在内连接结果中。

## 3.3 左外连接

左外连接（LEFT JOIN，也写作 LEFT OUTER JOIN）保留左表的全部元组。对于左表中在右表找不到匹配的元组，结果中右表的属性全部取 NULL。左外连接常用于“列出所有学生，包括没有选课的学生”这类需求。

## 3.4 ON 与 WHERE 的区别

ON 子句给出连接条件，决定元组如何配对；WHERE 子句在连接完成之后对结果元组进行筛选。对 LEFT JOIN 而言，如果把针对右表的条件（例如 e.term = '2026秋'）写在 WHERE 中，那些右表属性为 NULL 的补齐元组会因为比较结果为 UNKNOWN 而被筛掉，最终结果等同于内连接。若希望保留左表全部元组，应把右表条件写进 ON。

## 3.5 NULL 与三值逻辑

SQL 使用三值逻辑：TRUE、FALSE、UNKNOWN。任何与 NULL 的比较（包括 NULL = NULL）结果都是 UNKNOWN。WHERE 与 HAVING 只保留条件为 TRUE 的元组。判断空值必须使用 IS NULL 或 IS NOT NULL。

## 3.6 常见错误清单

错误一：LEFT JOIN 之后在 WHERE 中写右表条件，导致没有匹配的左表元组消失。修正方法是把右表条件移到 ON 中，或者明确改用 INNER JOIN。

错误二：使用 COUNT(*) 统计左外连接中右表的匹配数。补齐 NULL 的元组也会被 COUNT(*) 计为 1，应改用 COUNT(右表的非空列)，例如 COUNT(e.cid)。

错误三：用 = NULL 判断空值。应使用 IS NULL。
