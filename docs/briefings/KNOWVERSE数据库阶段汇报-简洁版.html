知屿 KNOWVERSE

一个把课程知识点种成花园的个人学习助手。这次主要讲两件事：前端做成什么样，以及数据库怎样把学习记录组织起来。

我们做了什么

知屿把学习过程做成一座花园：知识点是一株花，提问、练习、笔记和修正都会留下“学习证据”，证据让花从种子长到开花。学生可以回看自己学过什么、为什么到了这个阶段，也可以和班级同学一起学。

问答

围绕课程资料回答问题，并在正文里标出引用的是哪一版资料、哪一页/哪一段。

练习

按薄弱知识点出题；选择题、数值题和 SQL 题分开判分，SQL 在独立的只读数据库里跑，不会改到业务数据。

成长

每一条学习证据都会记录；花的状态、学习路线和周报都由这些记录算出来。

共学

班级星系里只能看到同学主动公开的内容；学习卡可以发布到班级。

前端设计：把数据库里的记录变成一座花园

前端不自己保存学习状态，只负责把数据库里的记录显示出来。页面按“我现在要做什么”分成六块，而不是按数据库表来分。

六个主入口

  • 花园：自己的花圃，花的状态就是知识点阶段。
  • 学习：对话、练习、学习卡。
  • 成长：学习路线、学习周报。
  • 回顾：历史问答、成长时间轴、记忆。
  • 资料：上传与查看课程资料。
  • 共学：班级星系、共学小组。
桌面顶栏手机底部导航键盘可操作

三个设计取舍

花园隐喻：知识点是花，证据是成长；学生不用先理解数据库表，也能知道自己学到哪。

3D + 2D 兜底：支持 3D 时显示可旋转的花园；不支持 3D 或开启低动效时，自动换成静态绘本，功能不丢。

移动端优先：手机把侧栏改成底部导航，面板单列显示；低动效模式关闭动画与粒子。

数据库设计：一类事实一张表

数据库是系统的唯一事实来源。核心思路只有一句话：不同的事实分开存，用外键把它们连起来。这样改一个标签不会动到回答，换一版资料也不会影响旧引用。

核心关系

表存什么为什么单独存
users账号、昵称、时区登录与个人设置
conversations / messages一次会话；每一条问题或回答回答通过 reply_to_id 指回原问题
concepts / message_concepts知识点；消息与知识点的关联多对多关系单独用关联表，标签有候选/确认/拒绝状态
materials / material_versions / material_chunks资料、版本、片段资料更新后旧引用仍指向当时的版本
message_citations某条回答引用了哪个片段、摘录了什么引用只保存编号和摘录，不重复存整段原文
attempts / evaluations一次作答；这次作答的判分作答和判分是两件事，开始作答时可能还没有评价
learning_evidence / learning_states学习证据；当前阶段与复习时间阶段由证据算出来，可回查“为什么是这个阶段”

三条约束规则

主键 + 外键：每张表都有主键；跨表引用用外键，数据库会拒绝指向不存在记录的写入。

必要的重复字段：messages 里保留 user_id 方便按用户过滤，但用“会话 ID + 用户 ID”的组合外键保证它和会话的归属一致。

版本不可变：资料、题目、学习卡都“身份表 + 版本表”；新版本不覆盖旧版本，旧引用仍可解释。

安全与并发

行级安全：23 张带用户数据的表启用行级安全；应用角色只能看到当前用户的行，不是靠每条 SQL 自己记得加条件。

一次结算一个事务：作答、评价、证据、阶段一起提交；中间失败整笔回滚。

重复提交：同一次作答重复提交也只结算一次，不会重复加证据。

一次真实的查询优化

历史问答要支持“按知识点找问题”。原来的 SQL 先给每个问题找最新回答，再检查标签；大部分问题根本没有目标标签，这一步就白做了。改写后先找带目标标签的消息，再取这些问答的最新回答。

同一份数据，前后对比（P95 指 95% 的请求在这个时间内完成）

场景并发原查询 P95改写后 P95
冷门知识点（每人 5 组）178.74 ms4.66 ms
冷门知识点（每人 5 组）4142.15 ms5.15 ms
热门知识点（每人 3000 组）1144.00 ms134.32 ms
热门知识点（每人 3000 组）4273.33 ms103.82 ms

4 万条合成消息；每名用户冷门命中 5 组、热门命中 3000 组；每组预热 2 次、测 20 次。计时只到数据库请求，不含浏览器和 HTTP。

结论：冷门知识点收益最大（约 17 倍）；热门也有改善。改写前后会比较返回行、顺序和总数，确保结果没有变。

当前完成情况与下一步

前端

花园、对话、练习、成长、回顾、资料、共学七个主面板；桌面与手机两套导航；3D 与静态绘本两种模式。

数据库

55 个关系；23 张表启用行级安全；资料/题目/学习卡按版本保存；核心流程用事务和约束保证一致。

验证

250 个测试用例、37 个测试文件通过；类型检查与生产构建通过；查询优化在 16 组条件下做了对比。

下一步

把测试数据扩大到更接近真实使用的规模；补浏览器到数据库的端到端延迟；继续整理报告与答辩材料。
