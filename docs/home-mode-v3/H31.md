### H31 应用只提交目标实例、取消完整恢复、一次应用一次撤销

- **要求**：应用只提交目标实例；取消完整恢复进入前颜色；一次应用是一次可撤销操作。
- **前置依赖**：H28/H12（历史栈）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：材质命令 `SetMaterialCommand` 只作用于选中对象，`history.execute` 一次即一个撤销步；本项目用 `decorStore.update(id, { parts })` 对齐——只改该实例、一次提交一步历史。
- **KolyaVol（MIT）**：取消是「丢弃草稿」而不是「再改回去」，本项目同理：工作台的颜色只是本地 state，取消即丢弃，从不写布局。

#### 第一遍实现
- 应用：`onApply(parts)` → `decorStore.update(it.id, { parts })` → 只改该实例 + 入历史；随后关闭浮层并提示「已应用 DIY 配色（可撤销回滚）」。
- 取消：只 `setDiyTarget(null)`，**完全不写数据**。

#### 第一遍审查（主动构造失败）
1. **[中] 应用与当前值相同时也写一条历史**：颜色没变也会 push 一步撤销（与 H12 的「空变换回收」不同，因为这里是 `update` 而非 `beginTransform`）。
2. **[低] 取消后预览的临时状态**：取消只丢弃本地 state，重开时重新从 `item.parts` 读取，符合预期。
3. **[待验] 「只改目标」的证据**：需要同时放两朵同类花，验证另一朵不受影响。

#### 第二遍实现（记录 #1 + 补 #3 证据）
- 本轮以「两朵同类花 + 只改一朵」的对照验证「只提交目标」；#1 记录为遗留（可在 update 前比较 parts 是否相同来跳过）。

  - 应用后目标 `parts = {petal:'#22aa55', leaf:'#8DAF78', stem:'#7C9B67'}`；
  - **点一次「撤销」→ 目标 `parts` 回到 `None`** ✓（一次应用 = 一次撤销）。
