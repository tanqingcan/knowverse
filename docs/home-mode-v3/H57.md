#### GitHub 候选对比与已读源码
- 端到端 Playwright 的写法要点：**每档独立 browser context**、全流程断言用「状态真值」（DOM + localStorage + 服务端 status）而不是截图；落位类操作要落在**星球可见区域**（不同宽高比下星球屏幕位置会变）。

#### 第一遍实现（`.dsh-tools/h57-flows.py`）
每档跑 10 个断言：进入创造（顶栏隐藏 + 快捷栏出现）→ 屏扫选中一个初始建筑 → 「移动」数值精调（左右滑杆值变化）→ 复制（对象数 +1）→ DIY（分区换预设并应用）→ 发布（服务端 `status=published`）→ 退出（快捷栏消失、顶栏恢复）→ 学习小窗（`main.focus` 在视口内）→ 刷新还原（内容签名一致）→ 全程无 pageerror。

#### 第一遍审查（主动构造失败）
1. **[高] 首次跑：环境 500**——我前一轮执行 `npm run build` 覆盖了 dev server 的 `.next`，导致 `/space`/API 全 500，三档全部卡在「进入创造」。**必须清 `.next` 重启 dev**。
2. **[中] 断言写错目标**：移动/复制断言读的是 `cottage`，但屏扫选中的是温室或种子棚 → 三档全报 FAIL（其实产品没问题）。
3. **[中] 竖屏 tablet 复制落位失败**：tablet 768×1024 是竖屏，星球屏幕位置与横屏不同，(cx−40, cy+60) 落到星球外 → 复制没生成。改为**落在选中对象屏幕位置附近**。
4. **[低] 「移动」浮层开着时点复制**：桌面/手机首轮复制也失败；先点「收起」再复制才稳定（浮层遮挡/干扰）。

#### 第二遍实现（修 #2/#3/#4 的测试写法）
- 移动/复制改用「选中项滑杆值」「装饰总数」判据；
- 复制落位点 = 选中对象屏幕坐标 +34px；
- 移动后先 `收起` 属性浮层；
- 清理 `.next` 重启 dev（#1）。
