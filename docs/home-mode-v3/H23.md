### H23 素材栏不拦截整页 pointer、按钮不穿透放置、拖画布不误触新增

- **要求**：素材栏不拦截整页 pointer 事件，点击按钮不穿透放置物件，拖画布不误触新增。
- **前置依赖**：H17/H19/H21。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：编辑器 UI 是 DOM 覆盖层，**只在自己的盒子里接收事件**；画布的 `onPointerUp` 用 `delta` 阈值区分「点击」与「拖拽」——本项目沿用同一判据（`e.delta > 6` 不放置）。
- 本项目结构：`.hotbar-wrap` / `.creative-palette` 都是尺寸受限的 DOM 覆盖层，其余区域直接落到 `.world` 画布。

#### 第一遍实现（结构已具备，本轮补证据）
- 点按类：快捷栏槽位 / 「全部素材」/ 退出 等按钮都是 DOM 元素，点击不会穿到 canvas；放置层 `sphereGeo(3.12)` 只在 `placingKind` 非空时挂载。
- 拖拽类：放置层的 `onPointerUp` 判断 `e.delta > 6` 直接 return；`.world` 的 pointermove 在 `decorDrag` 非空时走对象拖动分支。
- 覆盖层类：全量素材库是 260px 左面板（`libOpen` 才渲染），面板外区域仍是画布。

#### 第一遍审查（主动构造失败）
1. **[中] 测试语义易误判**：首版脚本「在画布空白处单击」时其实仍处于放置态（刚点过槽位），于是计数 +1——**这是正确行为**，不是穿透；后来把「点 UI 按钮后计数不变」与「拖拽后计数不变」分开判定。
2. **[低] 放置态下打开素材库再点画布**：仍会放置（库只遮 260px）。属产品取舍，记录不修。
3. **[低] 触屏 pointer 与鼠标 pointer 事件合并**：本轮未单独验证触屏 `pointerType`。

#### 第二遍实现（补齐判定与证据）
- 脚本拆成三个独立断言（UI 按钮 / 画布拖拽 / 纯单击），并在桌面与手机两档各跑一次。
- 修改文件：无代码改动（本轮为验收与判定修正）；证据脚本 `.dsh-tools/h23-24.py`。

#### 复审
- `.dsh-tools/h23-24.py`（1440×900 与 390×844 两档）：
  - **点快捷栏槽位 + 开/关素材库（E/Esc）→ 计数 15→15（unchanged=True）** ✓ 按钮不穿透；
  - **在画布上拖拽（放置态）→ 计数保持 16 不增** ✓ 拖拽不误触新增；
  - 关闭放置态后单击画布不新增（由 H21 的「放完退出放置」保证）。
- 无 pageerror。
