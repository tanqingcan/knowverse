### H14 统一保存新增/初始实例/群组参数；旧布局一次性迁移；加载失败不写默认

- **要求**：统一保存新增、初始实例和群组参数；旧布局一次性兼容迁移，不覆盖用户现有装饰；加载失败不静默写回默认布局。
- **前置依赖**：H03（迁移分支）、H04（群组）、H02（建筑实例）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：`history.toJSON()` 与场景序列化——保存必须覆盖**全部对象类型**，不能漏掉新增类型（漏掉就会在服务端校验里整单失败）。
- **KolyaVol threejs-editor（MIT）**：保存走统一场景序列化，不做「按类型分表」。
- 本项目对应：`decorStore.decor` 是唯一列表 → `saveLayout(revision, items)`，但**服务端 `VALID_KINDS` 白名单**是另一处必须同步的地方（本轮就是这里出的问题）。

#### 第一遍实现
- 保存链路：`saveCreative` → `PUT /api/planet-layout` → `saveDraft(user, baseRevision, items)`，`clean()` 逐项校验 kind/坐标/旋转/缩放/宽长。
- 迁移：`loadLayout` 分支（服务端无建筑 kind → 补入 `DEFAULT_HOME_LAYOUT`），见 H03。
- 群组参数：`grassGroup`/`wildflowerGroup` 作为布局项（`scale` 当密度）一并保存。

#### 第一遍审查（主动构造失败）
1. **[严重] 保存建筑/群组整体失败**：实测「保存到服务器」返回 **`保存失败：未知素材 cottage`** —— 数据库约束已在迁移 0005/0006 放开，但 **`src/server/layouts.ts` 的 `VALID_KINDS` 白名单仍是旧的 14 种**，导致任何包含建筑或群组的布局**整单被拒**（用户搬走/复制建筑后根本无法保存，这是 H02/H03/H04 成果落库的致命阻断）。
2. **[中] 加载失败是静默的**：`loadLayout().catch(() => {})` 什么都不做、也不提示，用户会以为布局丢了。
3. **[低] 迁移只发生一次**：由 H03 的分支保证（服务端一旦有建筑就以其为准）。

#### 第二遍实现（修复 #1/#2）
- **修复 #1**：`VALID_KINDS` 补齐 7 种建筑 + 2 种群组，并与 schema 约束的注释互相对应（避免下次再漂移）。
- **修复 #2**：`catch` 里 `setLayoutMsg` + `toast("布局加载失败：已保留本地草稿，可稍后重试", "error")`，明确告知且不写默认。
- 修改文件：`src/server/layouts.ts`、`src/components/space/SpaceApp.tsx`。
