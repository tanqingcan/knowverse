### H26 退出后业务 UI/视角/选择/路由恢复

- **要求**：退出后原业务 UI、视角、选择和路由合理恢复，原来关闭的窗口不被无故打开。
- **前置依赖**：H16（隐藏）、H25（退出流程）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：编辑器/查看器是同一画布的两套 UI 壳，切换壳时**不重建场景**；`signals.objectSelected(null)` 清空选择。本项目同理由 `creativeOpen` 切换 UI 壳，`doExit()` 清空 `selectedDecorId`。
- **KolyaVol（MIT）**：退出编辑回到浏览态，不自动打开任何面板。

#### 第一遍实现
- `doExit()`：`setCreativeOpen(false)` + 清空 `placingKind`/`selectedDecorId` + 关闭 `libOpen`/`slotMode` + 关闭 `askExit`。
- 业务 UI 由 `!creativeOpen` 条件渲染自然恢复（顶栏由 CSS `is-creating` 解除隐藏、`GardenHUD` 重新渲染）。
- 视角：退出**不调用** `resetView()`，保持用户当前镜头（避免「一退出就被拉回默认角度」）。

#### 第一遍审查（主动构造失败）
1. **[中] 「放弃本轮」二次确认**：退出流程里「放弃本轮」会再弹 `discard()` 的原生 confirm，交互重（已在 H25 记录）。
2. **[低] 选择残留**：若不显式清 `selectedDecorId`，退出后 `.world-selbar` 可能残留——本轮显式清空并在复审中验证。
3. **[低] 窗口意外打开**：`onExit` 不应触发任何 `open({panel})`——复审检查 panel 数量为 0。

#### 第二遍实现（验证 #2/#3）
- 复审用脚本显式断言「退出后 hotbar=0、selbar=0、panel=0、topnav=flex、hud=1」。

#### 复审
- `.dsh-tools/h26-27.py`（桌面 1440×900 与手机 390×844 两档）：
  - 进入创造前：`topnav flex | hud 1 | panel 0`；
  - 创造中：`topnav none | hud 0 | hotbar 1`；
  - **退出后：`topnav flex | hud 1 | hotbar 0 | selbar 0 | panel 0`** ✓（业务 UI 恢复、选择清空、无窗口被打开）；
  - URL 仍为 `http://127.0.0.1:3000/space`（路由未变）✓；
  - 两档均无 pageerror。
- **状态**：**双轮通过**
