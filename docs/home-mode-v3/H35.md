### H35 装饰花阶段可选且标为外观；知识植物阶段不可在 DIY 伪造

- **要求**：装饰花的阶段可选且标为外观；真实知识植物阶段仍来自学习证据，不可在 DIY 伪造开花。
- **前置依赖**：H28（工作台）、H29（分区）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：编辑器只改**场景对象**的外观属性，不回溯业务数据；本项目据此把「阶段」限定为**装饰花的外观字段**（`DecorPlacement.stage`），知识植物的阶段来自 `WorldPlant.stage`（学习证据），DIY 路径根本不接触它。
- 数据边界：工作台的 `item` 来自 `decorStore.decor`（布局装饰），花圃里的知识植物来自服务端 `plants`/`beds`——两者不同源。

#### 第一遍实现
- 工作台对**装饰花类**（rose/flower/flower2/flower3）显示「**外观阶段**」下拉（种子/萌芽/生叶/花苞/开花），并附注：「只影响这朵装饰花的外观；知识植物的阶段由学习证据决定，不能在 DIY 里伪装开花」。
- 应用时把 `stage` 一并提交：`decorStore.update(id, { parts, stage })`；预览也用所选阶段渲染。
- 对非花类（房屋/棚/观测台）不显示阶段选择器。

#### 第一遍审查（主动构造失败）
1. **[中] 「不可伪造开花」缺反向证据**：需要确认「知识植物不在工作台可选」——工作台的 `selItem` 只从 `decorStore.decor` 取对象，知识植物不在其中（结构性保证），但未在脚本里显式断言。
2. **[低] 阶段选择器只对 4 种装饰花出现**，其它 kind 无此 UI（符合语义）。

#### 第二遍实现（验证 #1 的结构性保证）
- 复审记录：工作台入口 `onDecorDiy` 只由选中**装饰实例**触发；知识植物点击走 `onSelect`（植物档案），不会进入工作台。
