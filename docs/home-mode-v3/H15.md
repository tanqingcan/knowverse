### H15 静态绘本/参观也从同份布局渲染、参观只读

- **要求**：静态绘本/参观也从同份布局渲染；如某资产静态视图尚不支持，提供明确近似图及记录，不回到错误固定位置。参观无法编辑。
- **前置依赖**：H09（`homePoses`/`doorOf`）、H02（实例化）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：一个场景数据对应多个「渲染后端」（WebGL / 静态导出），数据必须单一来源——本项目 3D（`GardenWorld`）与 2D SVG（`StaticGarden`）共用 `homePoses(decor)` 推导位置。
- 对比：`StaticGarden` 原本直接读 `SPOTS` 常量画建筑 → 属于「回到错误固定位置」，本轮改为读 poses。

#### 第一遍实现
- `StaticGarden` 增加 `decor` prop：用 `homePoses(props.decor)` 推导 `cottage/greenhouse/lamp/bench/sign/lampSpot` 的位置；回忆小径/温室小路端点也跟随当前建筑。
- 接线：`/visit` 页 `<StaticGarden decor={visitDecor}>`（参观用到的同一份发布布局）；`/space` 的降级视图 `<StaticGarden decor={decorStore.decor}>`。
- 参观只读：`/visit` 的 `<GardenWorld readOnly>` 已存在（H02 起建筑也从布局渲染）。

#### 第一遍审查（主动构造失败）
1. **[中] 静态视图原先把建筑画在 `SPOTS` 固定位置**：用户搬走书房后，2D 绘本仍画在老位置——正是目标里「不回到错误固定位置」禁止的情况。
2. **[中] 道路端点同样是写死的**：`memPts/greenPts` 末尾用 `SPOTS.cottage/greenhouse`。
3. **[低] 静态视图不显示用户摆放的装饰（花/围栏/泥土）**：SVG 是手绘构图，没有逐件渲染 —— 属「静态视图尚不支持的资产」，需在文档记录（本轮未加界面注记）。
4. **[低] 参观只读未在本轮重新取证**：`readOnly` 逻辑自 H02 起未改动。

#### 第二遍实现（修复 #1/#2）
- `StaticGarden` 的建筑/路灯/长椅/木牌/星灯停靠全部改用 `poses`；小路端点跟随。
- 修改文件：`src/components/world/StaticGarden.tsx`、`src/app/visit/page.tsx`、`src/components/space/SpaceApp.tsx`。
- 新增 `tests/unit/home-poses.test.ts`（4 例）：默认回落、实例移动后跟随、星灯停靠平移跟随、门口偏移随 yaw 旋转（180° 后落到另一侧）。

#### 复审
- 静态视图实测（`.dsh-tools/h15-static.py`，用 `--disable-3d-apis` 关闭 WebGL）：`canvas: 0`、SVG 宿主 13 个、**静态绘本出现「星灯书屋」按钮**，其 `transform=translate(950.02 434.27)` —— 与 `P(0.92,-0.92)` 手算一致（420 与 434 对应默认位置），说明确实按 poses 绘制。

- **记录**：静态视图不逐件渲染用户摆放的装饰/泥土/围栏（手绘构图限制）——按目标记为「静态视图尚不支持的资产」，未伪造「已渲染」。
