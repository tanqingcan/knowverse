### H11 数值/按钮精调、轴义清楚、缩放基点贴地、变换期间相机暂停

- **要求**：允许数值/按钮精调，方向轴含义清楚，缩放基点贴地；变换期间相机暂停，释放后恢复。
- **前置依赖**：H02/H10（拖动链路）。

#### GitHub 候选对比与已读源码
- **drei `TransformControls.tsx`（MIT）L88-93**：`controls.addEventListener('dragging-changed', e => defaultControls.enabled = !e.value)`——变换开始禁用相机控制、结束恢复。本项目对应实现是 `.world` 的 `pointermove` 在 `decorDrag.current` 非空时**直接 return**（不进入相机旋转分支），`pointerup` 时清空 `decorDrag.current`。
- **three.js `Editor.js`（MIT）**：数值输入走 `object.position` 的增量命令，与本项目滑杆 `onUpdate({x,z,rot,scale})` 对应。

#### 第一遍实现
- `CreativePalette` 属性面板新增两个位置滑杆：**位置 X（左右）** / **位置 Z（前后）**，范围 ±4、步长 0.05，显示两位小数；`selected.x/z` 与 `onUpdate({x,z})` 类型补齐。
- 缩放：`<group scale={d.scale}>` 挂在 `OnCap` 原点（球面表面点）→ **缩放基点贴地**（放大时不会整体抬离地表）。
- 相机暂停：既有机制（`decorDrag` 非空 → `.world` pointermove 直接 return）。

#### 第一遍审查（主动构造失败）
1. **[中] 相机暂停证据不足/疑似泄漏**：一次对象拖动后 `window.__gardenYaw` 从 `0.4197 → 0.4442`（+0.0245 rad ≈ 1.4°），说明**至少有一次 pointermove 泄漏到了相机旋转分支**；但释放后画布拖动 `yaw → 1.144` 说明相机能恢复。
2. **[低] 轴义**：X/Z 是「球冠平面」坐标，不是世界东西/南北；本轮通过标签「左右/前后」明确，但极点附近 Z 的直观含义仍弱。
3. **[待验] 缩放基点**：逻辑上 `<group scale>` 在表面点，但缺「放大后底座是否仍贴地」的视觉证据。

#### 第二遍实现（本轮部分）
- 新增位置 X/Z 数值滑杆（见上），使「数值/按钮精调」可检查。
- **相机暂停泄漏**：尚未定位到具体泄漏点（怀疑 pointerdown 与 R3F 事件顺序之间有一次 move），下一轮加 `window.__decorDragging` 探针精确定位后再修。
