### H08 编辑模式只选中、浏览模式恢复原入口

- **要求**：编辑模式点击建筑只选中，不打开学习/资料；退出后点击仍打开原功能。复制建筑可以共享同一入口功能，不创建重复业务记录，并在数据中明确语义。
- **前置依赖**：H02（`editing` 语义 + `BUILDING_HIT`）、H05（选中反馈）。

#### GitHub 候选对比与已读源码
- 复用 `docs/home-editor-references.md`：
  - **three.js `Editor.js`（MIT）**：`signals.objectSelected` 与「双击进入编辑」分离——选择/激活是两种语义，本项目用 `editing` 开关切换「点击=选中」与「点击=业务入口」。
  - **KolyaVol threejs-editor（MIT）**：编辑态下画布不再透传业务点击（画布只服务编辑）。

#### 第一遍实现
- `GardenWorld` 装饰循环的 `onPointerUp` 按 `isBld && !props.editing` 分流：
  - 浏览模式 + 有业务入口的建筑（cottage/greenhouse/observatory）→ `props.onHotspot(hit.name)`，**打开原业务面板**；
  - 浏览模式 + 纯装饰建筑（seedshed/arch/pond/sign）→ 不做事（保持「悬停标签」语义）；
  - 编辑模式 → `onDecorSelect(id)` 选中；
  - 非建筑装饰 → 沿用原逻辑（浏览时进入创造并选中）。
- 建筑热点 `BUILDING_HIT` 的 `name` 即业务入口 key；复制品保留同一 `kind` → 同一入口（共享），**不新建业务记录**（对话/资料仍是同一份）。
- 语义登记：入口语义来自 `catalog.ts` 的 `semantics/opens`（资产层单一来源），实例只存 `kind`，避免每实例复制一份语义造成不一致。

#### 第一遍审查（主动构造失败）
1. **[高] 浏览模式点建筑「模型」会进入创造模式**：实测浏览模式点建筑主体（非底座小圆柱 Hit）时走的是 `onDecorSelect` → `setCreativeOpen(true)`，用户想打开学习/资料却进了编辑器。**这是本次审查抓到的核心缺陷**。
2. **[中] 纯装饰建筑的浏览点击语义**：seedshed/arch/pond/sign 只有悬停标签，点模型原本也会进编辑器；修复后改为「不做事」，需要在文档写明。
3. **[中] 同一入口的重复记录风险**：若入口按「实例」建记录，复制 3 个书屋会有 3 份对话。当前入口 key 是 `hotspot name`（非实例 id），天然共享，已复核。
4. **[边界] 编辑模式退出后立即点击**：需保证 `editing` 已置 false（Esc 三级退出后才退出创造），否则仍只选中。

#### 第二遍实现（修复 #1/#2）
- 装饰循环 `onPointerUp` 改为按 `isBld && !editing` 分流（见上）。
- 修改文件：`src/components/world/GardenWorld.tsx`。
- **修复后复测**（`.dsh-tools/h08b.py`）：编辑模式在同位置点击 → `panel_open: 0`（不再打开业务面板）；浏览模式点击能打开业务面板（title 非空）；`tsc` 0；无 pageerror。
