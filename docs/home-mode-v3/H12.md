### H12 撤销/重做覆盖全部对象，单次拖动一步

- **要求**：所有初始对象支持撤销/重做，单次拖动只算一步；新增/复制/改色也进入历史。
- **前置依赖**：H02（实例）、H06（复制）、H07（改色）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：`history.execute(cmd)` / `undo()` / `redo()`，命令在**执行时**才记录——对应本项目「起手快照 + 结束提交」而不是逐帧压栈。
- **drei `TransformControls.tsx`（MIT）**：`onMouseDown` 记起点、`onMouseUp` 结束——与「一次拖动 = 一步」的时机完全一致。
- 对比：本项目原实现用 **400ms 时间窗合并**（`coalesce`）近似「一次拖动一步」，属于启发式；改为显式起手/结束。

#### 第一遍实现（在既有历史栈上改造）
- `decor.ts`：
  - `beginTransform()`：把「变换前」的完整快照压入历史、清空 redo，并置 `transforming` 标记；
  - `endTransform()`：清除标记；
  - `commit()` 在 `transforming` 为真时**不记录**——拖动/滑杆期间的所有中间态都不进历史。
- `GardenWorld`：装饰 `onPointerDown` → `onDecorTransformStart`；`.world` 的 `pointerup`（`decorDrag` 非空时）→ `onDecorTransformEnd`。
- `SpaceApp` 接线到 `decorStore.beginTransform/endTransform`。
- **第一遍证据**（`.dsh-tools/h12-undo.py`）：拖动观测台 `(-0.75,-2.15) → (-0.5594,-0.3499)`（约 1.6s 长拖动）→ **点一次「撤销」后数组与拖动前完全一致（`True`）**；「重做」后与拖动后一致；新增对象 14→15、撤销回 14；无 pageerror。

#### 第一遍审查（主动构造失败）
1. **[中] 空快照占一步**：`beginTransform` 在按下时就压栈；若只是「点一下选中」没有实际位移，`endTransform` 不会回收 → 撤销会出现「点了没反应」的空步。
2. **[中] 滑杆连续编辑**：按住方向键改滑杆会触发多次 `update`，仍靠 400ms 合并；极端快速连按可能产生多步（可接受，记录）。
3. **[待验] 复制/改色入历史**：二者走 `place`/`update` → `commit(record=true)`，与新增同一条路径；新增已实测，复制/改色未单独取证。

#### 第二遍实现（修复 #1）
- `endTransform` 增加「空变换回收」：`JSON.stringify(snap) === JSON.stringify(list)` 时 pop 掉那个快照，避免「点一下没动」也占一步撤销。
- 修改文件：`src/lib/decor.ts`。
- **修复后复测**：`h12-undo.py` 全项仍通过（一次撤销完全回到拖动前、重做一致、新增可撤销）；`tsc` 0；无 pageerror。
