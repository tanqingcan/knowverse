### H51 从数据库恢复六类对象；刷新、重登、另一个独立浏览器上下文同账号均相同

- **要求**：必须从数据库恢复「搬走的初始小屋+复制的小屋+不同 DIY 配色+新玫瑰+球面泥土+围栏」；刷新、重登、另一个独立浏览器上下文同账号均相同。
- **前置依赖**：H14（保存）、H34（parts 入库）、H03/H06（初始实例与复制）。

#### GitHub 候选对比与已读源码
- 持久化验收的成熟做法：**内容签名比对**而不是「看起来一样」——把布局归一化成 `(kind,x,z,rot,scale,parts,stage)` 的有序列表，在三处（保存后本地 / 刷新后 / 另一上下文）逐项相等才叫一致。
- 本项目已有 `toLayoutItem/fromLayoutItem`；服务端是唯一权威（`planet-layout` PUT/GET）。

#### 第一遍实现（`.dsh-tools/h51-restore.py`）
- 走真实 UI：选中初始小屋 → 搬走 → `Ctrl+D` 复制 → 新玫瑰 + DIY 改色 → 加围栏与泥土 → 保存 → 取签名 A → 刷新取 A2 → 另开一个浏览器上下文（同账号）取 B。

#### 第一遍审查（主动构造失败）
1. **[严重] 签名 A 与 B 不一致**：21 项里有 **1 项** 不同——都是同一朵玫瑰 `parts {leaf,petal,stem}`，A 是 `#8DAF78/#7C9B67`（大写），B 是 `#8daf78/#7c9b67`（小写）。**根因**：客户端默认色是大写、服务端 `validateParts` 统一转小写，于是"保存前后看起来不一致"。
2. **[中] 拖拽搬家不稳定**：首版用鼠标拖拽搬小屋，实测位置没变（`moved_ok=False`），取证不可靠。
3. **[中] Ctrl+D 落位点偏了**：复制预览在 (980,520) 落位失败，小屋数量没增加。

#### 第二遍实现（修复 #1/#2/#3）
- **颜色大小写归一**：`DiyWorkbench` 的初值/自定义取色/预设/恢复默认统统 `.toLowerCase()`；`layout-api.toLayoutItem` 对 `parts` 再做一次小写归一（旧本地数据兜底）——本地与服务端同口径。
- **搬家改用数值精调**（H22 的「移动」浮层 range setter），确定性优于拖拽；**复制落位改到星球中央附近**。
- 修改文件：`src/components/space/DiyWorkbench.tsx`、`src/lib/layout-api.ts`。
