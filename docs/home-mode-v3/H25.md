### H25 退出时未保存提示：保存并退出 / 放弃本轮 / 继续编辑

- **要求**：退出时未保存提示：保存并退出/放弃本轮/继续编辑；保存失败留在编辑并保留草稿。
- **前置依赖**：H14（保存）、H16（退出入口）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：编辑器退出/关闭前用 `history.changed` 判断脏状态；本项目用「最近一次成功加载/保存的布局快照 `savedSnap`」比对当前布局，等价于脏标记。
- **KolyaVol threejs-editor（MIT）**：未保存提示同样是三选一（保存/放弃/取消），本项目沿用该交互。

#### 第一遍实现
- `savedSnap` ref + `applyLayout(arr)` 包装（加载/恢复路径统一写快照）；`saveCreative` 成功后也更新快照。
- `isDirty()` 用 `decorRef` 取**最新**布局（避免 Esc 闭包拿到旧 decor）。
- 三条退出路径统一走 `requestExit()`：右上「退出创造」按钮、快捷栏「退出」、Esc 最后一级。
- 脏时弹 `.exit-mask` 三选一：**保存并退出** / **放弃本轮** / **继续编辑**。
- `saveThenExit()`：保存成功才退出；失败 `setLayoutMsg("保存失败：…（改动仍在，可重试）")` 并**留在编辑**，草稿不丢。

#### 第一遍审查（主动构造失败）
1. **[高] Esc 闭包拿到旧 decor**：`isDirty` 若直接读 `decorStore.decor`，Esc 的 `useEffect` 闭包会读到首次渲染的值 → 判定失真。改为 `decorRef.current`（每次渲染同步）。
2. **[中] 声明顺序**：把 `decorRef/isDirty` 插到了 `decorStore` 声明之前 → `TS2448 块级变量在被声明前使用`，必须挪到 `useDecor()` 之后。
3. **[待验] 保存失败路径**未做真实网络失败注入（代码上 catch 内只提示、不退出）。
4. **[待验] 「放弃本轮」**会触发 `discard()` 的二次确认（原生 confirm），交互略重。

#### 第二遍实现（修复 #1/#2）
- 修复 #1：`isDirty` 改用 `decorRef`。
- 修复 #2：把 `decorRef/isDirty` 移到 `const decorStore = useDecor(...)` 之后。
- 修改文件：`src/components/space/SpaceApp.tsx`、`src/app/globals.css`。
