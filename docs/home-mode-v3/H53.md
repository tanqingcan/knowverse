### H53 写接口拒绝其他账号与非法参数；revision 冲突不覆盖；网络失败保草稿；草稿/发布区别清晰

- **要求**：写接口拒绝其他账号和非法参数，revision 冲突不覆盖；网络失败保留草稿，草稿/发布区别清晰。
- **前置依赖**：H14/H34/H51（保存与校验）。

#### GitHub 候选对比与已读源码
- 写入接口的三道闸：**认证（是谁）→ 授权（这块数据是不是你的）→ 校验（参数合不合法）**，再加**乐观锁（baseRevision）**防并发覆盖。本项目顺序一致：
  - 认证：`/api/planet-layout` 走会话用户，匿名 401；
  - 授权：`findPlanet(user)` 只解析当前用户自己的星球，别人的布局连 GET 都拿不到；
  - 校验：zod（形状）+ `VALID_KINDS`/`num()`/`validateParts`（语义）；
  - 乐观锁：`baseRevision !== 当前 revision` → 409。

#### 第一遍实现（构造 11 类请求）
- `.dsh-tools/h53-api.py` + `.dsh-tools/h53-final.py`：未知 kind、x 越界、z 非数、非法部位、非法颜色、items 非数组、items 超限、baseRevision 落后、别的账号、匿名、并发发布。

#### 第一遍审查（主动构造失败）
1. **[中] 「其他账号」用例没有真正跑通**：`fresh` 账号登录成功但 `/api/planet-layout` 返回 **404「星球不存在或无权访问」**——它连自己的星球都没有，因此无法演示"写别人布局被拒"。这条只能以「demo 数据未被影响 + 越权访问返回 404」作为间接证据，**如实记录**。
2. **[待验] 网络失败是否真的保草稿**：需要 `context.set_offline(true)` 后点保存，检查本地装饰数量与提示文案。
3. **[待验] 草稿/发布是否有状态区分**：需要读回 `status/publishedRevision`。

#### 第二遍实现（补齐 #2/#3 的实测）
- 用 `set_offline` 注入真实网络失败；再恢复在线重试，验证草稿可继续保存。
