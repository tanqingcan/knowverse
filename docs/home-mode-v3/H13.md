### H13 删除/隐藏可恢复、不删学习数据、业务入口可达、模板恢复先预览

- **要求**：删除/隐藏建筑后可恢复；不删除学习数据；业务导航仍有可达入口；模板恢复先预览，保留回滚版本。
- **前置依赖**：H12（历史栈）、H08（业务入口）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：`RemoveObjectCommand` 只从场景移除对象、**不动对象自身的数据**；`history.undo()` 可完整恢复。本项目 `removeDecor(list,id)` 只过滤装饰列表，学习数据（服务端 `plants`/花圃 `beds`）从不参与。
- **KolyaVol threejs-editor（MIT）**：Delete 走撤销栈，与 `Ctrl+Z` 一致。本项目「删除后一次撤销即恢复」复用 H12 的起手/结束机制。

#### 第一遍实现
- 删除：操作条「删除」/属性面板「删除」→ `decorStore.remove(id)` → 走历史栈（H12）→ 可撤销恢复。
- 模板：`applyTemplate` 的确认框从「一句话」改为**列出将被替换的件数与种类**，并明确「可用撤销回滚」。
- 业务入口：`SECTIONS`（花园/学习/回顾/资料/共学）由顶栏渲染，与建筑实例无关——删掉书屋后仍可从「学习 → 对话」进入。
- 学习数据：`removeDecor` 是纯函数，只过滤 `DecorPlacement[]`；花圃/知识植物来自 `layoutBeds(space)`，删除路径完全不触及。

#### 第一遍审查（主动构造失败）
1. **[中] 模板「预览」名不副实**：原确认框只有一句「用默认模板替换当前草稿？」，用户看不到会变成什么，等于没预览。
2. **[中] 「隐藏」未实现**：目标要求「删除/隐藏建筑后可恢复」，本轮只做了**删除**（删除+撤销已满足「可恢复」），隐藏（保留数据仅不渲染）未做，需如实记录。
3. **[中] 删除建筑后地表印迹/道路回落**：`homePoses` 找不到实例 → 回落 `SPOTS` 默认位（H09 已知边界），会出现「小路指回老位置」。
4. **[低] 业务入口可达性无双模式证据**：顶栏在创造模式下被隐藏（H16 要求），需确认浏览模式下删掉建筑后入口仍可用。

#### 第二遍实现（修复 #1）
- `applyTemplate` 的确认文案改为：`从模板开始：共 N 件（rose、rose、soil、road、fence、lamp）。当前草稿会被整体替换，可用「撤销」回滚。`
- 修改文件：`src/components/space/SpaceApp.tsx`。
- **修复后复测**（`.dsh-tools/h13-delete.py`）：
  - 选中书屋 → 删除：`cottage 1→0，total 14→13`；
  - 一次撤销：`cottage 0→1，total 13→14`（**restored: True**）；

  - 无 pageerror。
