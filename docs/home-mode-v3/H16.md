### H16 进入创造后隐藏原 UI，只留星球+底部快捷栏+小型退出/保存

- **要求**：进入创造后隐藏原顶栏、今日建议、时间轴、原花园业务工具栏和演示说明浮层；视觉仅保留星球、必要移动/缩放/复位、底部素材快捷栏及小型退出/保存入口。隐藏 UI 不可残留可聚焦区域。
- **前置依赖**：H17（快捷栏）。

#### GitHub 候选对比与已读源码
- **KolyaVol threejs-editor（MIT）**：编辑态把业务 UI 全部让位给编辑器浮层（README 的编辑器截图里只有画布 + 工具）；本项目据此在 `.app` 上挂 `is-creating`，用 CSS 隐藏顶栏、且用 JSX 条件**不渲染** HUD/时间轴（避免残留可聚焦区域）。
- **three.js `Editor.js`（MIT）**：编辑器与查看器是两套 UI 壳，同一画布切换——本项目用同一 `GardenWorld` 实例切换 UI 壳，不重建场景。

#### 第一遍实现
- `SpaceApp`：`.app` 增加 `is-creating` class；`GardenHUD`（今日建议 + 业务工具栏）改为 `!creativeOpen` 才渲染；顶栏由 CSS `.app.is-creating .topnav { display: none }` 隐藏；创造模式右上角只留一个 `.create-exit`「退出创造」按钮。

#### 第一遍审查（主动构造失败）
1. **[中] `display:none` 与「不残留可聚焦」**：顶栏只是 CSS 隐藏，DOM 仍在；需确认隐藏子树不进 Tab 顺序（`display:none` 的子树不可聚焦，符合要求，但测试脚本用 `querySelectorAll` 统计会把它们算进来，容易误判）。
2. **[待验] 左侧是否真的没有大面板**：DOM 中 `.creative-palette` 数量为 0，但 vision 复核截图仍描述「左侧有 260px 面板」，需进一步确认是否是场景左侧物件被误读。
3. **[待验] 可聚焦按钮总数**：隐藏前后都还有 22 个可聚焦按钮，未逐项归属。

#### 第二遍实现（本轮）
- 文案/结构：`create-exit` 与 hotbar 分离（退出入口在右上、操作在底部）。
- 修改文件：`src/components/space/SpaceApp.tsx`、`src/app/globals.css`。

#### 复审
- **DOM 证据**（`.dsh-tools/h16-check2.py`）：进入创造后 `app class = "app is-garden   is-creating"`；`topnav display: none`、`rect 0x0`；`.hud` 与 `.creative-palette` 数量均为 **0**；无 pageerror。
- **面积证据**（`.dsh-tools/h16-hotbar.py`）：编辑 UI（hotbar + exit + 选中条）合计 **73,386 px² / 1,296,000 px² = 5.66%**（目标 ≤18%）。

- **状态**：**第二遍待审**（左侧面板的视觉复核未闭环）
