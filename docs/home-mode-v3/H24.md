### H24 手机槽位可横向滑动、点击目标 ≥44 CSS px、兼容安全区

- **要求**：手机槽位可横向滑动且点击目标不少于 44 CSS px，兼容安全区；不强行把 9 槽挤到不可点，提供触摸替代快捷键。
- **前置依赖**：H17（快捷栏）。

#### GitHub 候选对比与已读源码
- 复用 `docs/home-editor-references.md`：**fernforge-arcade/minecraft-clone（无 license，仅交互）** 的手机快捷栏为横向可滚 + 大按钮；**drei/three** 无相关实现。
- 本项目实现：`@media (max-width:560px)` 下槽位 48×56（≥44）、`.hotbar` 横向 `overflow-x:auto` + `scroll-snap` + `touch-action: pan-x`、底栏与退出按钮用 `env(safe-area-inset-*)`。

#### 第一遍实现
- CSS：移动端 `.hotbar-wrap` 改为 `left/right:8px` 撑满宽度（不居中挤压）、`.hotbar` 横向滚动、槽位 `min-width:48px`、侧边按钮 `min-height:44px`。
- 安全区：`bottom: calc(8px + env(safe-area-inset-bottom))`、退出按钮 `top: calc(8px + env(safe-area-inset-top))`。
- 触摸替代快捷键：槽位本身就是大按钮（点击即选），不需要数字键；「全部素材/连续/保存/退出」都在 ≥44px 的按钮里。

#### 第一遍审查（主动构造失败）
1. **[中] 390px 宽下 9 槽必然溢出**：9×48 + 间距 ≈ 492px > 390px → 必须横向滚动，不能压缩到 <44px（本轮选择滚动而非压缩）。
2. **[低] 安全区未在真机验证**：`env(safe-area-inset-*)` 的取值依赖设备刘海/手势条，桌面 Chromium 模拟无法证明。
3. **[低] 横向滚动的滚轮/触摸手势与「切槽滚轮」冲突**：桌面滚轮切槽逻辑在手机上不存在，触摸横滑是独立手势，需确认不互相触发。

#### 第二遍实现（验证 #1，记录 #2/#3）
- 在 390×844 视口实测：槽位 `48×56`、`.hotbar` `clientWidth 374 / scrollWidth 492` → **可横向滚动**。
- 修改文件：`src/app/globals.css`。
