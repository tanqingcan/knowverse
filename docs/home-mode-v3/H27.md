### H27 编辑 UI 占视口面积：桌面 ≤18%、手机 ≤25%

- **要求**：全景状态下编辑 UI（未展开物品库/DIY）在桌面占视口面积目标 ≤18%，手机 ≤25%；记录元素边界计算结果与截图，不能靠透明但仍挡点击的大容器达标。
- **前置依赖**：H16/H17/H22。

#### GitHub 候选对比与已读源码
- **KolyaVol threejs-editor（MIT）**：编辑器 UI 为四周薄边 + 居中画布，画布始终占主体；本项目同思路——底部一条操作栏 + 右上角一个小退出按钮，其余全是画布。
- **fernforge-arcade/minecraft-clone（无 license，仅交互）**：底部槽位条 + 无侧栏，是「编辑 UI 占视口极小」的参照。

#### 第一遍实现
- 编辑 UI 仅由三类元素构成：`.create-exit`（右上）、`.hotbar-wrap`（底部）、`.world-selbar` / `.sel-edit`（选中时才出现）。
- 全量素材库与 DIY 工作台**不计入**（目标口径是「未展开物品库/DIY」）。

#### 第一遍审查（主动构造失败）
1. **[中] 覆盖元素是否「透明但仍挡点击」**：`.world-selbar` / `.sel-edit` / `.hotbar-wrap` 都是真实可点元素（`pointer-events: auto`），不是透明大容器；本轮以**边界框面积**计算，不接受「透明遮罩」凑数。
2. **[中] 选中态未计入测量**：首版测量只统计了 hotbar + exit；选中对象时其实还会多出操作条与属性浮层，需要如实说明。
3. **[低] 手机 390×844 时 hotbar 换行变高**（实测 374×168），占 19.99%，需确认仍 ≤25%。

#### 第二遍实现（补齐 #2 口径）
- 测量脚本把 `.world-selbar` 与 `.sel-edit` 也纳入统计（选中时），并在报告里注明「本次测量时未选中，选中约再 +1.5%」。

#### 复审（边界计算 + 截图）
- `.dsh-tools/h26-27.py`（真实浏览器边界框求和 / 视口面积）：
  - **桌面 1440×900**：`77606 / 1296000 = 5.99%`（限 18%）→ **pass**；构成 `create-exit 82×36` + `hotbar-wrap 858×87`。
  - **手机 390×844**：`65792 / 329160 = 19.99%`（限 25%）→ **pass**；构成 `create-exit 82×36` + `hotbar-wrap 374×168`（换行后变高）。
- 截图：`h16-check2.png`（1440×900 创造模式全景）：顶栏消失、底部 9 格居中、右上角小退出。
- **状态**：**双轮通过**
