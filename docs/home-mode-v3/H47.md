#### 第一遍实现（接线现状）
- `useDialog(focusWinOpen, focusWinRef, closePanel, fallback)` 已存在；`main.focus` 带 `role="dialog" aria-modal="true" tabIndex={-1}`。

#### 第一遍审查（主动构造失败）
1. **[高] 焦点进入、Tab 陷阱、滚动锁定全部失效**：实测打开后 `activeElement = BODY`、连按 14 次 Tab 有 **前 8 次跑到窗口外**（页面顶栏/HUD），焦点陷阱形同不存在。
   **根因**：`useDialog` 传的是 `focusWinOpen`（**面板态**），而 H43 的星落动画让窗口**延后 700ms 才挂载**——`useDialog` 的 effect 在面板态一变就执行，此时 `ref.current === null`，于是 `first?.focus()` 与 Tab 处理全部落空。
2. **[中] 「窗口打开时禁止背后物件编辑」**：现有实现靠 `aria-modal` + 覆盖层 + 滚动锁定；未做背景 `inert`，点击窗外空白仍可能触发场景 raycast（本轮未构造该用例）。
3. **[未验证] 输入法（IME）**：桌面 Chromium 无法真实模拟中文输入法组合态。

#### 第二遍实现（修复 #1）
- 把 `useDialog` 的 active 参数改为 `focus`（= 面板存在 **且星落已结束、窗口已渲染**）；并把 `const focus` 声明提前到 `useDialog` 之前（否则 `TS2448 块级变量先用`）。
- 修改文件：`src/components/space/SpaceApp.tsx`、`src/app/globals.css`。
