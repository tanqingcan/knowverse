### H28 选中花或房屋 → DIY 独立工作台

- **要求**：选中花或房屋→DIY→独立工作台，展示该对象的大型可旋转预览、颜色分区、色板、应用和取消；返回时仍选中原对象、原镜头位置不丢失。
- **前置依赖**：H22（DIY 入口）、H07（材质隔离思路）。

#### GitHub 候选对比与已读源码
- **KolyaVol threejs-editor（MIT）**：材质编辑是**独立浮层**（画布 + 材质面板分离），编辑结束回到场景且选中对象不变；本项目采用同一结构：`.diy-card` 覆盖层内含独立小 `Canvas`，主星球 `GardenWorld` **不卸载**。
- **three.js `Editor.js`（MIT）**：材质修改通过命令入历史；本项目应用时走 `decorStore.update(id, { parts })` → 历史栈，可撤销回滚。
- 未采用：不引入 drei 的 `OrbitControls`（未安装），预览旋转用 10 行指针拖拽 + 自动慢转实现。

#### 第一遍实现
- 新增 `src/components/space/DiyWorkbench.tsx`：
  - 左侧**大型预览**：独立 `<Canvas>`（环境光 + 主光 + 补光）+ 模型自动慢转 + **拖动旋转**（`prefers-reduced-motion` 下不自动转）；
  - 右侧**颜色分区**：按 kind 给出分区（玫瑰/花卉：花瓣·花心·叶片·茎；小屋/温室/观测台/棚：屋顶·墙面·门窗·饰边等），每区一个色块 + 名称；
  - **色板**：6 套绘本暖光协调预设 + 自定义取色 + 「恢复本部位默认色」；
  - 底部「取消 / 应用」，并注明「应用只改这一个对象；可用撤销回滚」。
- `DecorPlacement` 新增 `parts?: Record<string, string>`（按部位名存色值）。
- `SpaceApp`：`diyTarget` 状态；H22 的 DIY 按钮从占位 toast 改为**打开工作台**；应用时 `decorStore.update(id, { parts })`。

#### 第一遍审查（主动构造失败）
1. **[高] parts 只存不渲染**：`parts` 已写入布局数据，但**模型自身还没读取分区颜色**——3D 场景里看不出部位变化（预览只用了「第一个部位色」作整体 tint 的近似）。这是 **H29** 的建模任务，本轮如实记录，不冒充已按部位上色。
2. **[中] 预览 tint 的选取规则粗糙**：`parts.petal ?? parts.roof ?? parts.roofGlass ?? parts.dome` 是兜底链，不同 kind 的「主部位」语义不同。
3. **[低] 取消路径未在脚本中单独验证**（代码上 `onCancel` 只关浮层、不写数据）。
4. **[待验] 返回后选中/镜头是否保持**：浮层是覆盖层、主场景不卸载，理论上保持；未显式取证。

#### 第二遍实现（修复 #2 并明确 #1 归属）
- 预览 tint 改为按 kind 取「主部位」映射（`PRIMARY_PART[kind]`），不再是 `??` 链乱猜。
- 修改文件：`src/components/space/DiyWorkbench.tsx`。
