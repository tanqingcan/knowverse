### H18 1–9 切槽、滚轮在栏上切槽/画布上缩放不串扰、输入框不拦截

- **要求**：1–9 切换槽位；滚轮在操作栏上切槽、在画布上缩放镜头，禁止互相串扰；输入框聚焦时保持正常输入。
- **前置依赖**：H17（快捷栏）。

#### GitHub 候选对比与已读源码
- 复用 `docs/home-editor-references.md`：**fernforge-arcade/minecraft-clone（无 license 声明，仅交互）** 的「1–9 选槽 + 滚轮切槽」；**drei/three 的相机控件** 用滚轮缩放——二者在同一屏共存时必须区分作用域（指针在栏上还是画布上）。
- 本项目实现：数字键走全局 `keydown`（排除输入控件）；滚轮**用原生非 passive 监听**绑定在 `.hotbar` 上，`preventDefault + stopPropagation`；画布滚轮仍由 `.world` 的 `onWheel` 处理。

#### 第一遍实现
- `SpaceApp` 新增 keydown effect：`1-9` → `hotbar[n-1]`（再按同槽取消）；`E` 打开全量素材库；`INPUT/TEXTAREA/SELECT/contentEditable` 或带修饰键时不拦截。
- `CreativeHotbar` 增加 `onWheelSlot`；滚轮切换槽位。
- `SpaceApp` 的 `libOpen` 加入 Esc 层级（先关库）。

#### 第一遍审查（主动构造失败）
1. **[高] 滚轮完全不起作用，且画布滚轮会切槽（串扰）**：用 React `onWheel` 时实测「在栏上滚轮 → 槽位不变」「在画布滚轮 → 槽位变了」——**方向完全相反**。原因是 React 19 把 wheel 作为 passive 监听挂在根节点，`preventDefault/stopPropagation` 不可靠。
2. **[低] 同槽再按一次取消**：本轮实现为二次取消，需验证不误清空放置态。

#### 第二遍实现（修复 #1）
- `CreativeHotbar` 改为 **原生 `addEventListener('wheel', h, { passive: false })`**（`useRef` 绑定 `.hotbar` 节点，`useEffect` 注册/清理，回调经 `cbRef` 转发避免重复绑定）。
- 修改文件：`src/components/space/CreativeHotbar.tsx`。
