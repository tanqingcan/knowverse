#### 第一遍审查（主动找失败）

#### 第二遍实现（重做证据 3/4：`.dsh-tools/h38-retry.py`）
- 把流程改成**确定性**：先明确放一朵玫瑰并选中 → 先给它 `petal #d81b60` → 再 `Ctrl+D` → 在**另一处**落位 → 断言玫瑰数量 +1 且 id 不同 → 在**复制品**上改 `petal #00bcd4` → 对比原件与复制品。
- 证据 4 改为把「带 parts 的对象映射」写入 `h38-result.json`，并对「刷新前后」用**有序 parts 值**比对（不再用 id，见下方发现）。

#### 复审中的重要发现（回链 H51）
- **刷新后对象 id 会重新生成**（`fromLayoutItem` 用 `s-${Date.now()}…`），所以「跨会话一致」**不能拿 id 比对**；正确判据是「按 kind+位置/顺序的 parts 值与布局内容一致」。服务器还会把颜色 hex 统一成小写。
- 第一遍证据 4 之所以显示不一致，正是用 id 比对的误判——**已改判据并记录**。
