### H39 记录 A0；新窗面积控制在 A0 的 1/4～1/3

- **要求**：先记录当前 1440×900 学习窗外框面积 A0；默认新窗面积控制在 A0 的 1/4～1/3，记录实测尺寸与比例。不要把宽高都缩到 1/3。1280×720 参考约 440×380，按实际原窗口与可读性调整，无法同时满足时如实记录取舍。
- **前置依赖**：无（本项是第四组起点）。

#### GitHub 候选对比与已读源码
- 学习窗本质是**对话框**：参考 React/three 生态通用做法——小尺寸居中卡片 + 内部滚动 + 可主动放大（`KolyaVol` 的材质浮层同样是「小浮层 + 内部滚动」，不是整页铺开）。
- 本项目现状：`.focus` 是 `top: nav+14; bottom: 26; left:0; right:0; width:min(880px,…)` 的**整块高面板**，这就是审核里「遮挡 59%」的来源。

#### 第一遍实现（A0 记录 + 尺寸收口）
- **A0 实测**（`.dsh-tools/h39-a0.py`，真实点击「学习」入口打开 `main.focus`）：

| 视口 | 旧窗外框 | 面积 | 占视口 |
|---|---|---|---|
| **1440×900** | **880×800** | **704,000 px²** | **54.32%** |
| 1280×720 | 880×620 | 545,600 px² | 59.20%（与审核里「880×620、约 59%」一致） |

- 新窗：`position: absolute; top:50%; left:50%; transform: translate(-50%,-50%)`，`width: min(480px, 100vw-40px)`、`height: min(380px, 100vh-170px)`；入场动画改用 `kv-rise-c`（否则 `translateY` 会覆盖居中位移）。

#### 第一遍审查（主动构造失败）
1. **[高] 只缩了 CSS 容器，内容结构没重构**：窗口内仍是原来的「大面板内容」（会话列表 `478×98` 默认展开、输入框在底部大块）。这正是审核要求「不能只缩 CSS 容器」要打掉的做法——**内容重构属 H41/H42**，本项不宣布通过。
2. **[中] 1280×720 下同尺寸占本地 A0 的 33.4%**：略高于 1/3。因为 A0 判据以 1440×900 为准（25.9% ✓），1280 参考值按「可读性优先」保留，如实记录。
3. **[低] 入场动画 keyframes 冲突**：已修（`kv-rise-c`）。

#### 第二遍实现（待办，与 H41/H42 联动）
