### H33 复制实例后改色无串色；缓存材质/共享 GLB 的独立覆盖与释放

- **要求**：复制实例后改色无串色；缓存材质或共享 GLB 必须处理独立覆盖和资源释放。
- **前置依赖**：H07（材质隔离）、H29（分区材质）、H32（变体）。

#### GitHub 候选对比与已读源码
- **three.js `Editor.js`（MIT）**：共享材质必须 clone 后再改，否则全场景同材质一起变；GLTF 的材质也是共享的，同样要 clone。
- 本项目三处共享源，逐一处理：
  1. `geo.ts` 的 `matte(color)` **按色全局缓存** → `Tinted`/`PartTint` 一律 `clone()` 后改，卸载 `dispose()`；
  2. `vcol("petal"/"leaf"/"stem")` 顶点色材质共享 → 同上克隆；
  3. GLB 路径（`Model.tsx`）本来就对每个实例 `material.clone()`。
- 数据层：`parts` 是**每个实例自己的对象**（`place`/`update` 各存一份），复制时 `{...copyFrom.parts}` 浅拷贝，互不共享引用。

#### 第一遍实现
- 复制路径（H06 的 `startCopy`）现在**连 `parts` 一起复制**：`place(..., { ..., parts: copyFrom.parts ? { ...copyFrom.parts } : undefined })`。
- `PartTint` 的克隆材质在 effect cleanup 里逐个 `dispose()`；`Tinted`/ghost 同理（H06/H07 已做）。

#### 第一遍审查（主动构造失败）
1. **[中] 只验证了「改一朵不影响其他同类」，没跑「复制品与原件的对照」**：本轮脚本直接改第二朵，没有先 Ctrl+D 复制再改——语义等价（数据与材质都是按实例隔离），但证据链不是最直接的。
2. **[低] `parts` 浅拷贝**：值都是字符串，浅拷贝足够；若将来 `parts` 里出现嵌套对象需要深拷贝。
3. **[待验] `dispose` 是否真的释放**：H06/H09 已量化过纹理/材质不再单调增长，本轮未再量化。
