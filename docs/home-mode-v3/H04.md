### H04 环境登记与地表/群组编辑语义分离

- **要求**：天空、恒星/远景、星球本体作为环境设置登记，编辑语义与地表家具分开说明；所有地表建模默认可编辑；大量程序化草/野花可作为区域群组选择和调整密度/位置，明确操作单元，不能悄悄排除。
- **前置依赖**：H01（目录）、H02（建筑实例化）。

#### GitHub 候选对比与已读源码
- 复用 `docs/home-editor-references.md`：**three.js `Editor.js`（MIT）** 的 `sceneBackgroundChanged/sceneEnvironmentChanged/sceneFogChanged` 与 `objectAdded` 是**两组独立信号**——说明「场景环境」与「场景对象」在架构上就应分开管理；本项目据此把天空/恒星/星球本体登记为 `category: "environment"` 且 `editable:false`，草地/野花登记为 `group:true` 的群组。
- **drei PivotControls** 的局部锚点思路不适用于「全星球群组」——群组没有单一锚点，操作单元只能是密度，故不引入手柄。

#### 第一遍审查（主动构造失败）
1. **[高] 群组被当成可放置素材**：初版目录给 `decor.grassGroup` 也 `placeable:true`，素材栏会列出「草地（群组）」并可单次放置——违反「整组、不逐株」的操作单元定义；H01 测试「可放置覆盖」也随之失败。
2. **[中] 密度滑杆每次变化都重算 scatter**：`useMemo` 依赖 `grassDensity`，拖动滑杆会连续重建 720 个草实例（低性能设备上抖动）；当前靠 80ms 绘制节流缓解，未做「松手才提交」。
3. **[低] 环境项无 UI 只读展示**：环境 4 项只在目录数据里，界面上只有一句文案，没有列出「天空主题/星点数」等只读信息。
4. **[边界] 密度越界**：滑杆范围 0.2–2，而 `clampDensity` 允许 0.2–3（服务端 store 可写 5）——UI 与夹取范围不一致。

#### 第二遍实现（修复 #1/#4）
- 修复 #1：`PLACEABLE_ASSETS` 排除两种群组（`placeable: d.kind !== "grassGroup" && ...`）；素材栏列表过滤掉群组；H01 测试改为「目录长度 − 2」并断言群组 `placeable` 为假。
- 修复 #4：滑杆范围与 `clampDensity` 对齐（UI 0.2–2 ⊂ 0.2–3），并在文档记录「超出 2 只能通过数据/历史版本出现，加载时夹取」。
- 修改文件：`src/lib/home/catalog.ts`、`src/components/space/CreativePalette.tsx`、`tests/unit/home-catalog.test.ts`。
