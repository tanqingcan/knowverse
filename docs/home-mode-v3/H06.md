### H06 复制进入跟随指针预览，点击确认，取消无幽灵

- **要求**：复制生成新实例 ID，进入跟随指针的预览，点击确认；取消不留下幽灵对象。Ctrl+D 和按钮都可用；新对象不与原物件完全重叠。
- **前置依赖**：H02（复制基础）、H05（操作条按钮）。

#### GitHub 候选对比与已读源码
- 复用 `docs/home-editor-references.md`：
  - **three.js `Editor.js`（MIT）**：`AddObjectCommand` 只在**执行时**才把对象加进场景，之前不产生任何副作用——对应本项目「预览阶段不进数据、确认才 commit」。
  - **KolyaVol threejs-editor（MIT）**：Duplicate 走「复制 → 跟随鼠标 → 点击落位」的思路（README 描述），本项目据此把复制从「原地偏移」改为**预览确认**。
- 未采用：不做 drei 的 HTML 预览层（`Html`），沿用本项目世界内的 ghost 网格。

#### 第一遍实现
- `SpaceApp`：`copyFrom: DecorPlacement | null`；`startCopy(id)` 记录源实例参数并进入 `placingKind` 预览；Ctrl+D 与「复制」按钮都走 `startCopy`（不再直接落位）。
- `decor.ts`：`place(kind, x, z, opts?)` 支持带源实例的 `rot/scale/color/stage/width/length`，保证「预览 = 最终结果」。
- `GardenWorld`：新增 ghost——`placingPreview` + 指针移动时命令式写 `position/quaternion`（不触发 React 重渲染）；材质**克隆后**降到 0.55 透明度，避免影响真实实例；底座加 honey 色环。
- `onPlace`：复制预览确认时带源参数落位并选中新实例；Esc / 取消按钮清空 `copyFrom`。
- **第一遍证据**（`.dsh-tools/h06-copy.py`）：
  - 选中后 `Ctrl+D` → 总数 **14→14**（只是预览）+ 放置提示条出现；
  - 按 `Esc` → **仍 14**（无幽灵对象）；
  - 再 `Ctrl+D` + 点击球面 → **14→15**，新实例 `kind=greenhouse, x=0, z=0.35, rot=26, scale=1`（源参数被保留），无 pageerror。

#### 第一遍审查（主动构造失败）
1. **[高] ghost 材质克隆未释放**：每次进出预览都会 `clone()` 一批材质，若切 kind/反复预览，旧克隆没有 `dispose()` → 显存单调增长（正是 H55 要抓的泄漏类型）。
2. **[中] 「复制」按钮路径未独立验证**：测试只走了 Ctrl+D；按钮 → `duplicateDecor` → `startCopy`，同一条路径但未单独取证。
3. **[中] 预览提示条靠 `.cp-placing` 存在性判断**：该元素是素材栏的放置提示，复制预览时文案未区分「复制」与「放置」，用户可能分不清。
4. **[边界] 连续 Ctrl+D**：预览中再按 Ctrl+D 会用新源覆盖 `copyFrom`，已验证不重复创建。

#### 第二遍实现（修复 #1）
- ghost 的 `useEffect` 收集所有克隆材质，**cleanup 时逐个 `dispose()`**，避免反复预览造成显存累积。
- 修改文件：`src/components/world/GardenWorld.tsx`。
- **修复后复测**：`h06-copy.py` 仍通过；`tsc` 0；单测 42/42；无 pageerror。
