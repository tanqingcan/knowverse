# 资料流水线与检索设计

## RAG 在学习系统中的位置

答疑先根据当前会话读取学习目标和关注的知识点，再从 PostgreSQL 检索该用户有权读取的教材片段。回顾类问题还检索用户本人的历史问答；启用跨会话记忆时，当前任务也可使用学习者自述和会话摘要。三种上下文承担不同用途。教材用于支持课程结论，历史用于回答“我以前问过什么”，自述用于调整讲解方式或复习建议。它们共用课程、用户、会话等关系键。

模型生成后，服务端把回答、带原文摘录的片段引用、知识点候选分别落库。引用连到生成时的资料版本，标签挂到学生的问题上。知识点得到确认或用户完成作答后，正常业务流程按证据更新学习状态。后续查询可继续以该知识点定位资料和历史问题。推荐练习与更新掌握阶段有自己的业务规则。

教材召回的页码级评测覆盖这条链中的资料分支和回答引用。迁移 `0032` 增加片段级审核和持久向量。更大规模的索引和独立课程语料评测可在部署环境继续做。

## 学生私有资料与原文件

「原文提取」是把 PPTX 的正文和备注、PDF 的文字层等转成带位置的可搜索文本。系统保存上传原件和解析出的片段两份内容。直接处理 PPTX 或文本 PDF 时，片段保留幻灯片号或 PDF 页码。已有 Markdown 目前按标题与段号定位。要从 Markdown 回到对应 PPT/PDF 页，需要核对导出格式中的页码标记和原件对应关系。图片和没有文字层的扫描件需要 OCR。

- 「我的资料」是默认入口。学生可批量上传多份到同一个学科，系统逐份处理并反馈结果。上传已有资料的版本时一次提交一份。
- 文件目录由 `UPLOAD_DIR` 指定。新原件按 `用户 ID/版本 UUID` 存放，公共示例使用独立目录。PostgreSQL 保存所有者、版本、相对路径、SHA-256 和解析状态；片段另存并可检索。旧版平铺路径仍可读取。
- 通过资料详情的版本按钮选出版本，再走登录后的下载接口。下载与检索都检查当前用户可见范围。上传保存失败的版本会记录失败状态，恢复存储后可作为新版本重试。
- 在全新部署库将 `SEED_DEMO_DATA` 设为 `false` 后运行 `npm run db:seed`，只初始化学科、知识点和题库。样例课件与演示账号由常规演示初始化提供。服务器上让 `UPLOAD_DIR` 指向应用账户可写的持久目录，备份时将 PostgreSQL 和该目录一起保存。浏览器本地副本可用于离线阅读；后端检索和跨设备访问读取服务器已同步的版本。

### 课程材料扩充后的 RAG

导入一批课件前先辨认重复导出、预习版和课堂版，校对文本以及原页信息。相同正文可用文件散列或正文散列对照；同一资料的不同版本保留自己的版本号。新版资料可供新问题检索，历史回答按已有片段 ID 回原版。

资料页可以按知识点查到具体页或段，并跳到同一知识点的历史问答。在原文片段旁可确认、排除候选，也可手动选同学科知识点。同一个资料版本的不同片段独立判断，保留目录命中词、来源与审核时间。

### 持久向量与混合检索（迁移 0032）

|表|键和用途|
|---|---|
|material_chunk_concepts|主键 (chunk_id, concept_id)。引用片段和目录，记录候选、确认或排除。|
|material_chunk_embeddings|主键 (chunk_id, model_key)。保存编码器生成的 512 维单位向量；模型标识带权重和配置的指纹。|

上传完成后直接保存已解析片段和知识点链接。配置本机 BGE 后，上传接口尝试写入第一批向量。索引任务处理长文剩余片段、历史数据与临时失败，每批独立提交，以缺失的向量行作为待办。首次回填也会补历史片段的目录关联，并保留已经人工审核的链接。

检索时对问题编码，PostgreSQL 限定本人及可读公共资料、课程、每份资料最新可用版本和当前模型指纹，再在这个范围内精确比较持久向量。词法、知识点关联和向量各自产生排序，应用按名次加权融合。可以拆开的多问句分别召回，再分配结果名额。编码器不可达或向量查询超时时，词法和知识点关联继续工作。数据库当前按精确点积扫描合格向量，数据库表本身承担权限与版本范围；测试语料超过旧版的 192 段上限。

正式启用先运行 `npm run db:migrate`。启动 `scripts/local-rag.py` 并设置 `RAG_LOCAL_PORT`，再运行 `npm run rag:index` 回填。部署时可单独运行 `npm run rag:index -- --watch` 自动处理后续缺项。编码进程只监听本机。开发或演示可留空该端口使用词法和目录检索。

## C2 资料处理（2026-11-11）

上传 → 大小/文件头校验 → 保存原文件和版本元数据 → 事务外提取 → 短事务写片段、状态与知识点候选。API 在读取文件为 Buffer 前检查 10 MB 限制，服务层也保留检查。数据库结构和前端接口沿用现有设计。

|类型|处理方式|定位|
|---|---|---|
|TXT|UTF-8，按空行分段；拒绝含 NUL 或 PDF/ZIP 头的伪装文本|非空文本块段号|
|Markdown|识别1–6级标题，标题无需用空行隔开；围栏代码中的标题符号保持正文|标题路径与段号，标题也占段号|
|文本PDF|按页提取，规范化部首字符，长页分块|原PDF页码|
|PPTX|按演示文稿顺序读取正文；根据每页关系文件解析演讲者备注；排除备注页码、页眉页脚占位符|原幻灯片页码，heading注明备注|
|Word/Excel|保留现有文件名、MIME、大小、SHA-256、版本和存储位置；检查OOXML ZIP及对应主部件存在，正文不提取|状态说明区分Word/Excel|

长片段上限700字符；优先在后半段的句子/换行边界切分，无法找到边界时硬切。相邻长片段最多重叠80字符；不跨页、段落或标题边界拼接。长度按JavaScript字符串计数，不是模型token。

## 状态约定

- `ready`：已有可引用文本。
- `needs_ocr`：PDF文字层过少或PPT没有可提取正文/备注；仅提示OCR，不执行OCR。
- `unsupported`：已保存元数据，类型不支持正文提取；有效Word/Excel属于此类。
- `failed`：文件损坏或Office包内容与扩展名不一致。
- 文件超限、空文件、明显伪装扩展名在上传入口拒绝，不创建成功版本。

旧资料版本和引用不重算。改进仅作用于后续上传，若要体验可上传为新资料或新版本。

## 本地收尾版的教材到问答流程

1. **保存资料。** 原文件写入上传目录。PostgreSQL 保存资料标题、版本、文件散列和存储路径；提取出的正文单独按版本写入片段表。文本 PDF 保留原页码，PPTX 以演示文稿顺序编号，每页备注回到同一页。包内绝对路径和相对路径都可定位幻灯片；已声明的页缺失时报告具体失败页。图片页、图表中的标注与数学排版仍需要人工抽查。
2. **找一段能用的材料。** 系统先限定可见资料、指定学科以及每份资料最近的 ready 版本。数据库从正文或小标题命中的片段取最多 40 个候选，应用按词组覆盖、已知概念、标题与命中位置排序，常规对话取前 4 段。书名可以帮助排序，只有书名命中的无关页无法当选。学生问“什么是时隙归并窗口？”或直接用引号圈出这个词，系统可以按原词在正文查找，即使目录里还没有该知识点。
3. **回答和引用分工。** 数据库决定可供选择的片段；真实模型在回答中选择编号并提交摘录；服务端核对编号、正文标记和连续原文（允许排版空白差异）。摘录缺失或不匹配时，资料型回答最多再请求修复一次。修复失败只保留首次已经通过检查的引用。演示模式按固定逻辑选材，数据库可用片段开头作展示摘录。编号和摘录正确只表明这段文字确实存在，某句结论是否由它支持仍需判断。
4. **保存知识点。** 上传时以名称、别名匹配并累计命中的片段数，得到 material_concepts(version_id, concept_id, status, hit_count)。它记录“这一版涉及什么”。答疑时，message_concepts(message_id, concept_id, source, status) 记录“这个问题在问什么”；目录外的模型建议先写 concept_suggestions。个人上传的资料标签由上传者确认或排除，阅读操作要引用该版本中已经确认的知识点，才写 learning_evidence。用户确认的消息标签与取自教材的引用可以分别查询。

用现有样例可复现三项检查。① 上传带备注的 PPTX，查“星灯备注实验”，结果应回到第 1 张幻灯片的备注。② 上传条件概率 PDF，查“贝叶斯公式”，结果应包含第 3 页的原文。③ 在同名教材中放入 45 段无关练习，第 46 段才解释标题里的术语，结果应只选解释段。文件、查询、预期页码和权限断言见 [检索集成测试](../tests/retrieval.test.ts)。

### 下一轮怎样衡量 RAG 值不值得升级

先选本课允许使用的两个章节和一份课件，让一名组员标出问题、可接受的版本及页码、支持回答的原句，另一名复核。有多种正确出处时都记入答案。题目覆盖定义、同义改写、需要两段证据、教材无答案、换版和私人资料隔离；留出部分问题，只在实现确定后用于验收。

|需要作出的判断|记录什么|结果决定什么|
|---|---|---|
|正文是否正确入库|抽查原文件、页号、备注、公式和表格；标记不可提取页|若金标准原文根本未入库，优先修解析或对这些页做 OCR|
|正确页能否进入模型上下文|有依据问题中前 4 段含正确出处的比例；另记多段题是否找齐|若主要漏在同义改写，比较现有词法检索与词法加向量的结果|
|回答是否有据|逐句核对关键结论与摘录，分别记录支持、矛盾和资料未说明|若正确页已召回而结论仍错，优先改回答、拒答或证据展示|
|能否在课堂使用|同一批题记录检索 P50/P95、端到端耗时、无答案题的拒答情况|比较收益与等待时间，再决定是否引入新的模型服务|

版本级标签服务于资料目录，片段级关系复用同一 concept_id，历史回答继续指向生成时的片段。先前评测的 38/40 是旧轮次的有资料题有效引用覆盖率。

### DeepSeek 真实答疑

使用同一批题走正常对话服务，真实模式调用 DeepSeek V4 Pro，回答和引文都写入隔离 PostgreSQL。每题要求仅依据教材。首轮对照之后，给教材模式加上逐小问引用的提示，减少与问题无关的额外结论。两轮均保留输出，新旧两次生成有随机性。

|指标|首轮|逐小问引用提示复测|
|---|---:|---:|
|成功完成并保存|20 / 20|20 / 20|
|有依据题最终引用覆盖全部标注证据|10 / 16|14 / 16|
|无依据题明确说明缺乏依据|4 / 4|4 / 4|

### 本地启用与复跑

1. 安装 Python 的 `sentence-transformers`，下载 `BAAI/bge-small-zh-v1.5` 的权重与配置。已有模型目录可以直接复用。见 [BAAI 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)。
2. 运行 `python scripts/local-rag.py --model <模型目录> --port 8879`。在项目服务的环境变量或 `.env` 中设置 `RAG_LOCAL_PORT=8879`，运行 `npm run rag:index` 回填，再启动应用。有可用 CUDA 的机器可加 `--device cuda`。
3. 用已迁移并播种的本机 `knowverse_test` 作为 `DATABASE_URL`，运行 `npm run eval:textbooks -- test-results/textbooks.json --demo --scale`。此轮保存对话与引用，加入大批量自编片段、同名隔离和跨两讲问题。留空 `RAG_LOCAL_PORT` 可以只评估词法和目录关联。加 `--live` 可用已配置的真实模型复跑。脚本每次创建两个隔离评测账号。
4. 在正常对话中，问题可另起一行加“请仅依据本课程教材回答。”。有依据的回答保留引文，依据不足时显示提示。默认答疑仍支持标明通用知识。
