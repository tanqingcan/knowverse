设计日期：2026-11-21。建议题目：**知屿 KNOWVERSE：基于学习记录与关系数据库的个人学习助手**。

## 三、逐章详细目录与写作内容

### 摘要、关键词（C 起草，完稿后全员确认）

### 第 1 章 需求分析（B）

- **1.1 背景与目标**：历史问答难整理、资料难溯源、练习与状态割裂；先解释数据管理目标，再讲花园呈现。
- **1.2 用户、角色与场景**：学生、同班成员、实际只读角色/管理员工具；网站用户角色与数据库角色分清，不新增不存在的教师后台。
- **1.3 功能与优先级**：必选、推荐、增强分开。每项编号、输入、输出、成功和失败条件。
- **1.4 数据与业务规则**：会话—消息、消息—知识点、资料—版本—片段—引用、版本—作答—评价、证据—状态。列 8–12 条可检查规则。
- **1.5 非功能需求**：持久化、隔离、并发、恢复、可复现、响应式、可访问性；性能目标与实测分列。
- **1.6 需求追踪与范围**：需求编号→实现→测试；说明 demo/live、2D 班级星系。

交付：用例图、需求表、业务规则表。依据：[需求矩阵](../requirements-matrix.md)、[功能说明](../features-explained.md)。用例图不是 ER。

### 第 2 章 概要设计（C）

- **2.1 总体架构**：浏览器→Next.js 页面/API→业务服务→数据访问层→PostgreSQL；外部模型、文件存储、独立 SQL 沙箱各在何处。
- **2.2 模块职责与依赖**：身份、问答、检索、资料、练习成长、协作；不只贴目录树。
- **2.3 数据流与信任边界**：一次答疑、一次作答，标外部调用、校验、事务、用户上下文。模型不直接连接业务库。
- **2.4 技术选择**：PostgreSQL 是管理持久数据、查询、约束和事务的关系数据库管理系统，16 是主版本；其他框架各做什么。版本号本身不是亮点。
- **2.5 接口与异常约定**：选 5–8 个真实接口，列输入、输出、权限和错误；完整索引放附录。
- **2.6 演示与真实模式**：demo 不调用模型，live 调外部服务；共同持久化链路与不同评价方式分清。

交付：总体架构图、模块表、概要数据流。依据：`src/app/api/`、`src/server/`、`src/db/index.ts`、[智能体说明](../agent.md)。

### 第 3 章 数据库设计（A，全文重点）

每个概念先用普通中文解释，再给符号、列和 SQL。顺序是事实→概念→关系→规范化→约束与访问。

**3.1 建模范围与数据域**：划分身份、知识、学习世界、问答、资料、练习成长、协作、运维。区分概念 ER、逻辑关系图、物理访问结构。2026-11-17 快照为 55 个逻辑表、106 FK，排除分区子表与视图；封稿重导，保留真实日期。

**3.2 教材式 ER**：使用 [高级 Chen 主图](../er/advanced/03-learning-model.png)，解释 13 实体、12 菱形、21 椭圆和消息角色 ISA。按资料版本链、消息知识点链、作答证据链讲。图例说明键、基数、双线全参与。未画全部属性是可读性取舍，紧接局部图和字段表。版本有全局 ID，不能因 CASCADE 或名称就画成弱实体；消息 ISA 仍单表存储。

**3.3 ER 到关系模式**：实体、1:N、M:N、带属性联系、自关联、ISA 各给真实映射。核心字段至少三组：会话/消息/知识点关联；资料/版本/片段/引用；题目版本/作答/评价/证据/状态。列名、类型、可空、PK/FK/UQ、含义与少量示意行，同一组 ID 贯穿存取。`chunk_id→version_id→material_id` 找来源，quote 是本次选取摘录。

**3.4 候选键、FD、规范化**：解释唯一确定一行、属性由谁决定；宽表的更新/插入/删除异常；局部分解、二元无损连接判据、依赖保持。精讲 4–6 个已核对关系。可空 UNIQUE、部分唯一、超键不直接当全局最小候选键；代理主键不消除其他键上的部分依赖。使用 [最新范式复核](../schema/normalization-analysis.md)，不再给全库范式计数或 4NF/5NF 宣称。

**3.5 受控冗余与便利性**：messages.user_id 对 `(conversation_id,seq)` 部分依赖，严格不满足 2NF；复合 FK 保证归属。当前状态、倒排、汇总分别说明维护/对账、读收益与写成本。跨表可重算不自动导致本表违反 3NF；期望少一次 JOIN 不等于已实测加速。

**3.6 完整性与业务约束**：PK/FK/UQ/NOT NULL/CHECK、复合 FK、延迟约束；精选引用、消息归属、本命花、先修防环、成员资格、幂等。区分约束、触发器、事务函数与应用校验，给错误写入和并发结果。

**3.7 查询语义与物理设计**：先讲输入、返回行、排序，再讲选择、连接、去重、聚合和分页。重点是先找“问题本身或最新回答带标签”的问题 ID 集合，去重后取本人问答。例：Q1 最新 A2，旧 A1 带 K，A2 和 Q1 都不带 K，则筛 K 应排除 Q1；两路都命中也只返回一组。给原/改写 SQL 核心、等价验证、扫描变化；这次改写没有新增索引。B 树、GIN/倒排、部分索引按真实需求解释，保留覆盖索引负优化。数字统一在 6.5。

**3.8 事务、并发与恢复**：模型调用放事务外，前后短事务保存 pending 和回答/引用/标签。作答锁定、幂等复查、评价/证据/状态/事件/outbox 同事务；核对外部评价边界。并发同提交、最后名额、中途故障三例。outbox 原子写入与可靠消费分开，积压不隐去。

**3.9 数据库安全**：owner/kv_app/kv_sandbox；事务局部身份→RLS；甲乙用户越权读写、无上下文、池复用，必须用非所有者测。受控班级分享与函数权限。23 张 RLS 是快照覆盖信息，不等于全部表同策略；参数化、固定 search_path 与最小权限不等于绝对安全。

**3.10 视图、时态、审计与演进**：视图/物化/增量的新鲜度，审计分区与有效证据重放的区别，0000–0031 演进摘要。CDC、在线 DDL、批处理等已验证专项简述或附录，核心建模优先。

交付：Chen 主图 1、局部图 2、映射表、三组核心字段/示例、分解图、约束表、事务/权限图、查询流程图。55 表全景作高清附件。

依据：`src/db/schema.ts`、`drizzle/`、[ER 图册](../er/advanced/README.md)、[目录快照](../er/advanced/schema-metadata.json)、[候选键](../schema/candidate-keys.md)、[范式](../schema/normalization-analysis.md)、[查询对照](../sql/history-optimization.md)。旧第 3 章和宽表说明须纠错后再用。

### 第 6 章 系统测试与实验（D 汇总）

- **6.1 策略环境数据**：单元、真实 PG 服务、HTTP、浏览器、性能分层，日期、代码版本、角色、模式、规模。
- **6.2 功能异常（C/B/D）**：按需求编号测试答疑、检索、版本引用、练习、重试、证据修正。
- **6.3 完整性事务并发（A）**：错误 FK/归属、重复结算、并发幂等/名额、故障回滚、状态对账，给前后行数和结果。
- **6.4 权限沙箱（A/D）**：双用户、无上下文、池复用、非法写入、安全和等价；用例覆盖不是全面安全证明。
- **6.5 查询优化（A 写、C 审、D 复现）**：冷门/热门指**命中量小/大，不是冷/热缓存**。同 4 万消息/两用户，相同条件/权限，owner/kv_app、并发 1/4、预热 2 次、每组 20 请求。先证完整行/顺序/总数相同，再比 P50/P95/吞吐/扫描。四个 kv_app 场景全列；含连接事务、不含 HTTP/浏览器；合成数据、小样本和固定先后顺序限制保留。
- **6.6 来源检索质量（C，简写）**：命中、摘录合法、语义正确分开。50 问为 40 有资料+10 无资料，38/40 有效引用不等于 95% 答案准确率；8 主题改写不作 50 独立主题；没有人工金标准如实说。记忆同样给来源/失效/控制指标。
- **6.7 E2E 与界面（B/D）**：时间、浏览器、视口、WebGL；2026-11-17 的 15/15 主流程是静态降级，不扩大成 3D 全流程。
- **6.8 缺陷与局限**：至少三个真实案例，旧行为→定位→修复→回归→剩余风险，保留失败和负优化。

### 第 9 章 总结、局限与计划（C 汇总）
