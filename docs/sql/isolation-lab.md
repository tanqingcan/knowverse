# 并发异常实验室（实测）

> 由 `npm run lab:isolation` 于 2026-10-27T15:12:55.972Z 生成。两个真实连接按固定交错执行，
> 不是理论推演；数字与错误码来自 PostgreSQL 16.14 的实际返回。

| 实验 | 预期 | 实际 | 结果 |
|---|---|---|---|
| 丢失更新（READ COMMITTED，无锁） | 110（B 覆盖了 A 的更新） | 110 | ✅ |
| 丢失更新（SELECT … FOR UPDATE） | 120（串行化，无丢失） | 120 | ✅ |
| 不可重复读（READ COMMITTED） | 两次读到不同值：100 → 130 | 100 → 130 | ✅ |
| 不可重复读（REPEATABLE READ） | 两次读到相同值：100 → 100 | 100 → 100 | ✅ |
| 幻读（READ COMMITTED） | 第一次 0，第二次 1 | 0 → 1 | ✅ |
| 幻读（REPEATABLE READ） | 两次都是 0（快照隔离） | 0 → 0 | ✅ |
| 写偏移（REPEATABLE READ） | 两人都看到 2 人值班，各自下线 → 最终 0 人 | 两人看到 2/2，最终 0 人 | ✅ |
| 写偏移（SERIALIZABLE） | 后提交者 40001，最终仍 1 人 | 40001，最终 1 人 | ✅ |
| 咨询锁（同一时刻只有一个持有者） | A 拿到，B 拿不到；A 释放后 B 能拿到 | A=true B=false 释放后B=true | ✅ |

## 结论

1. **READ COMMITTED** 是 PostgreSQL 默认级别：每条语句看最新快照，因此会出现丢失更新、不可重复读与幻读。
2. **REPEATABLE READ** 在 PG 里是快照隔离：同一事务内读到的数据不变，幻读也消失；但**写偏移**仍可能发生（两个事务各写自己的行，没有写写冲突）。
3. **SERIALIZABLE** 用 SSI 检测危险结构，写偏移的后者提交时收到 `40001`，需要应用重试。
4. 本项目对应的取舍：
   - 作答结算用 `SELECT … FOR UPDATE` + 唯一索引，等价于“对同一行/同一键串行化”；
   - 共学名额用触发器内 `FOR UPDATE` 锁小组行，避免“先查后插”的竞态；
   - 对话生成不在事务里，失败重试靠状态机（`pending → failed → pending`）而不是隔离级别；
   - 需要跨行不变量的地方（如班级容量）把规则放进数据库，而不是靠 SERIALIZABLE 全局重试。
