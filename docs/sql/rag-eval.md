# C4 RAG 检索与引用评测

日期：2026-11-11。真实服务：DeepSeek V4 Pro。基线检索冻结于 `scripts/eval-legacy-retrieval.ts`。

## 方法

50条固定问题：8个课程主题各5种问法，共40条有资料问题；另10条要求仅凭资料回答的无资料问题。使用公共种子资料和独立禁用登录评测账号，不读取其他用户私有数据。不是50个独立知识点，也没有人工标注的语义金标准。完整问题、参考片段、回答、引用和失败均保存在 `../test-evidence/rag-eval.json`。

基线与改进版各50次直接模型生成（隔离检索与引用步骤，不运行工具循环与格式修复）。改进版在修复PDF换行处理后复测50次，初轮结果保存在 `../test-evidence/rag-eval-initial.json`。因此共150次生成调用。真实模型有随机性，结果不代表稳定统计显著性。

## 实测结果

|指标|基线|改进版|
|---|---:|---:|
|成功生成|50/50|49/50|
|有资料问题Top-4命中主题词条件|40/40|39/39已记录，1条生成失败未保留召回结果|
|有资料问题至少一条有效引用（问题级覆盖率）|40/40|33/40|
|引用片段满足主题词条件（引用级代理指标）|64/74|52/61|
|无资料问题明确说明依据不足|10/10|10/10|

主题词命中并非引用语义准确率。引用覆盖率按问题计算，不是回答句子的逐句覆盖率。改进版有1条非法JSON失败；线上智能体有一次格式修复，本评测未启用，不能据此声称线上必然失败。

结论：可比较的已记录问题检索命中已饱和，没有观察到命中率提升；严格校验使引用覆盖率下降。不能声称整体回答质量提升，也不能把未通过校验的引用自动解释为通用知识。当前改进主要是更透明的来源验证和失败处理，后续需补充更难、更独立的主题与人工审阅。

## 引用支持性辅助审阅

用同一模型、独立评审提示对回答与资料进行辅助判断，存在自评偏差；一条生成失败的问题不纳入成对比较。49对可比结果中：基线73条引用被判支持；改进版61条引用中24条被明确判支持，其余37条为不确定（包含评审未覆盖的编号，按不确定处理）。此结果显示当前自动审阅协议不足以提供可信的语义准确率，不能把不确定当作错误，也不能默认当作正确。逐条审阅记录见 `../test-evidence/rag-review.json`，需人工继续复核。

## 实现

- 召回上限40个候选，按去重后的检索词组覆盖、知识点别名、标题/章节命中及首次命中位置重排。相同正文在同版本内去重。只召回最新 ready 版本，版本号不跨不同资料直接比较。
- 同版本、同页、序号连续的已召回片段在上下文中合组呈现，各片段保留独立编号、ID和原文，不虚构合并后的数据库片段；不额外拉取未命中的邻居。
- 新提示词要求短连续原文quote。引用必须同时出现在正文和引用列表，编号可用；提供quote时，去除排版空白后必须是对应片段子串。拒绝跨片段冒引、假编号和孤立引用。
- 为兼容已有演示输出，未提供quote的旧格式不拒绝，轨迹单列为unverifiedQuotes；不能称为已验证原文。即使quote真实，也不能自动证明整个结论成立。
- 声称资料依据但无引用通过时，标记basis=insufficient并加“资料不足”提示。通用知识回答仍按原依据标签处理。通过的摘录保存到原有message_citations.quote，保留资料版本定位。

## 复现

配置真实模型后执行 `npm run eval:rag`；随后执行 `npm run eval:rag:review`。会产生真实调用费用，每次创建独立评测账号；原始证据应先备份，结果文件会被覆盖。类型检查与完整回归在本轮通过：19个文件、154个用例。浏览器交互未单独验收。

## 向量对照（设计讨论，未实测）

本次未引入pgvector或向量依赖。用real[]保存向量并逐行计算SQL余弦需要扫描候选并计算距离；没有近邻索引时，不能把普通数组列称为向量索引。生产大规模语义检索可再比较pgvector/HNSW，必须另行实测EXPLAIN与召回质量。本轮不提供虚构执行计划。
