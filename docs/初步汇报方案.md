# 知屿 KNOWVERSE · 课堂初步汇报方案（无 PPT）

> 思路：**不用 PPT，就让系统本身当“幻灯片”**。全程投屏三样东西：浏览器里跑着的系统、一张 E-R 图、一个终端。
> 讲的顺序是：一句话说清做什么 → 现场演示已实现的功能 → 数据库设计亮点 → 进度与下一步 → 问答。
> 主线约 6 分钟；老师给的时间短时，用文末的 3 分钟压缩版。

## 二、汇报流程（约 6 分钟）

### 第 1 段 · 开场定位（30 秒）｜画面：系统首页

> “我们组做的是课程给的‘个人学习助手’题目，名字叫**知屿 KNOWVERSE**。
> 核心想法是：每个学习者有一颗自己的星球，**学科是花圃，知识点是植物**。你在系统里提问、练习、答对题，对应的植物才会生长——植物的每一次成长都对应数据库里一条真实的学习证据。
> 技术上是 B/S 架构：Next.js 前端 + PostgreSQL 16 数据库。下面我直接演示已经做出来的部分。”

### 第 2 段 · 现场演示已实现功能（3 分钟）｜画面：系统

按 `docs/demo-scripts.md` 的三分钟版走，每一步只说一句话，**重点点出它对应作业的哪项要求**：

| 操作 | 说的话（对应作业要求） |
|---|---|
| 点“以演示账号进入” → 点主花圃的“左外连接”植物 | “这是演示账号的星球，每株植物是一个知识点，右边档案写了它现在的阶段和成长依据。” |
| 点 **问星灯**，问：`LEFT JOIN 之后把右表条件写在 WHERE 里，为什么结果像内连接？` | “**必选功能一：个性化答疑。**回答会结合当前知识点和资料，下面列出引用的资料、版本号和页码。” |
| 点引用“资料1” | “点引用能直接定位到资料原文。这是**推荐功能：教学资料整理**——上传的 PPT、PDF 会被拆成带页码的片段存进库。” |
| 回答下方点 **做练习** → 引导练习，故意提交错误 SQL（见 demo-scripts） | “**推荐功能：薄弱点训练。**学生写的 SQL 会在一个独立的只读沙箱库里真实执行，再和参考答案比对，所以能指出‘条件写在 WHERE 里了’。” |
| 顶部 **历史** → 关键词 `LEFT JOIN` 检索 → 再加日期和知识点筛选 | “**必选功能二：历史问答梳理。**按关键词、日期、知识点组合检索，在服务端一条 SQL 完成，只能查到自己的记录。” |
| 点结果卡片 → 回到原会话、原消息高亮 | “点结果能回到原来那条消息，接着问下去。” |

> 如果时间宽裕，再点一下顶栏“成长”→“学习路线”，一句话：“这个学习路线是用**递归 CTE** 一条 SQL 算出来的，先修知识一定排在前面。”

### 第 3 段 · 数据库设计亮点（1–1.5 分钟）｜画面：E-R 图 → 终端

这是数据库课，**这一段是得分重点**，挑 3 点讲，不要贪多：

1. **E-R 图与模式**（切到 `er-overview.svg`）
   > “我们按教材的 Chen 表示法画了 E-R 图，目前落地为 48 张表。像‘资料版本’‘资料片段’是弱实体，用双线矩形表示。”
2. **安全性：权限放在数据库里**（切终端，跑 `npm run security:audit`）
   > “应用不是用超级用户连库，而是用一个最小权限角色 `kv_app`，关键表开了行级安全策略。哪怕代码里漏写了 user_id 条件，数据库也只返回自己的数据。”
3. **完整性：约束交给数据库，还能自证**（跑 `npm run verify:invariants`）
   > “外键、CHECK、触发器三层约束；我们还写了一组不变量自检，比如‘植物阶段必须和学习证据一致’，现在全部 0 错误。”

> 老师追问 SQL 细节时，再打开 `docs/sql/core_queries.sql` 讲历史检索那条语句。

### 第 4 段 · 进度与下一步（1 分钟）｜画面：可以就停在终端或首页，口头讲

> “总结一下目前进度：”

| 状态 | 内容 |
|---|---|
| ✅ 已完成 | 两项必选功能（个性化答疑、历史检索）；两项推荐功能（资料整理、薄弱点练习）；数据库模式、E-R 图、迁移脚本；行级安全、约束与触发器、存储过程结算；自动化测试 X 个（以今晚 `npm test` 实测为准） |
| 🔧 基础版 / 待完善 | 班级星系与共学小组（基础版）；**真实大模型模式还没有做端到端验证**，目前演示用的是演示模式；资料检索是关键词检索，还不是向量检索 |
| 📋 下一步 | ① 接入真实模型并做端到端测试；② 复核范式分析与候选键，修订报告中的范式论证和课程章节对照；③ 实验报告定稿、补齐分工；④ 端到端回归测试与答辩彩排 |

> 收尾一句：“以上是我们的初步进度，请老师指导。”

**分工怎么讲**：如果是全组一起上台，按分工四条线各讲自己那段最自然——
数据与身份（A）讲第 3 段；呈现与宇宙（B）负责操作演示；检索与智能（C）讲答疑和历史检索；集成与交付（D）讲测试和进度。名字请按 `docs/division.md` 的实际分工填上。

## 四、问答预案

| 可能的问题 | 回答要点 |
|---|---|
| 大模型用的是哪个？ | 支持任何 OpenAI 兼容接口；课堂演示用的是**演示模式**，不调模型，但消息、引用、证据都是真实写库的。真实模式已写好，端到端验证是下一步。（**不要说已经接好了真模型**） |
| 表为什么这么多？ | 按实体拆分到 BCNF 为主；少数表保留了受控冗余（如子表冗余 user_id 便于权限判断），每处都有复合外键或自检兜底。详见 `docs/schema/normalization-analysis.md`。 |
| 植物成长是怎么判定的？ | 只看后端确认的学习证据：提问、引导练习、独立作答没做过的变式题，不是聊天次数。 |
| 学生写的 SQL 会不会把库搞坏？ | 在独立的沙箱库里，用只读角色执行，有 2 秒超时，业务库连 CONNECT 权限都收回了。 |
| 用大模型辅助设计数据库了吗？ | 用了，过程记录在 `docs/llm-assisted-design.md`：候选方案 → 审查 → 修改 → 理由。 |
| 还有什么没做好？ | 直接按“待完善”那一行说，老实讲反而加分。 |

## 五、注意事项

- **初步汇报不要过度承诺**：能现场演示的就演示，没验证过的（真实模型、真机 3D 帧率）明确说“还没验证”。
- 文档里的数字口径不统一（有的写 44 张表，有的写 48 张；`src/db/schema.ts` 当前是 48 张），**课上统一说 48 张**，测试数量以今晚实测为准。
- 演示时别临场打字：把要问的问题和 SQL 提前复制到记事本里，直接粘贴。
- 3D 卡顿就切“静态绘本”，不影响功能演示。
