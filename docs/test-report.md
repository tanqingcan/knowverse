# 系统测试报告

> 本报告只记录**实际执行过**的测试。执行环境：开发容器（Linux，Node.js 22.23，PostgreSQL 16.15，Chromium/Playwright 无头浏览器，WebGL 由 SwiftShader 软件渲染）。执行日期 2026-10-26。

## 1. 自动化集成测试（Vitest，真实 PostgreSQL）

- 命令：`npm test`（使用独立测试库 `knowverse_test`：每次重置 → migration → seed）
- 结果：**4 个文件，47 个用例，全部通过**，用时约 12 秒。完整输出：`docs/test-evidence/vitest-output.txt`
- 测试直接调用服务层函数与数据库，不经过浏览器；“真实模式”用例连接的是测试内启动的**本地模拟 OpenAI 兼容服务**，用于验证真实调用路径的错误处理，不代表任何真实大模型的效果。

| 需求中的检查项 | 对应用例（节选） |
|---|---|
| 个性化上下文是否正确 | get_learning_context 只读取本人目标、焦点阶段与本会话近期消息；他人会话不能作为上下文 |
| 时间、关键词、知识点及组合检索 | 英文关键词大小写不敏感；时区自然日边界（台北 23:30 与次日 00:10）；知识点筛选；三条件组合 |
| 中文关键词和分页 | 两字中文词“分母”、四字词“左外连接”；`%`/`_` 不当作通配符；13 条结果按 5 条分页，页间不重复、倒序 |
| 结果定位原消息 | 打开会话窗口包含目标消息与其回答；他人打开返回 not_found |
| 刷新后恢复 | 继续提问后重新读取会话仍在；users.last_conversation_id 已更新（另见 E2E“刷新后恢复会话”） |
| 不同用户数据隔离 | 历史检索、会话窗口、打标签、个人资料与个人题目对他人不可见 |
| 引用版本与位置一致 | 引用的片段页码/段落/版本号与数据库一致；上传新版本后旧引用仍指向第 1 版 |
| 重复请求幂等 | 同一幂等键重复提交只结算一次；5 个并发重复提交只产生 1 条评价 |
| 状态事务失败回滚 | 注入故障后评价、证据、状态、成长事件、outbox 均未写入，作答仍为 open，同一键重试成功 |
| API 超时和资料解析失败 | 模型超时 → failed + timeout 元数据，重试成功；非法 JSON → invalid_output；HTTP 500 与缺 Key 明确失败；伪造扩展名、非 UTF-8、空文件被拒绝；扫描件 needs_ocr；损坏 PPTX failed |
| 增强功能的并发名额 | 6 个用户并发争抢 1 个剩余名额，恰好 1 人成功、5 人收到 group_full |
| 其它 | 成长规则（引导/独立/变式/熟题重复/提示降级/自述不推动/撤销重算）；SQL 沙箱（只读、不能连业务库、超时、多语句拒绝）；先修防环；伙伴匹配只用公开意愿；outbox 投递；模型生成新题须通过结构校验与沙箱验证 |

## 2. 端到端冒烟测试（真实浏览器）

- 脚本：`tests/e2e/demo-flow.mjs`（按 `docs/demo-scripts.md` 三分钟流程操作，已按新的“花园 / 学习 / 回顾 / 资料 / 共学”导航更新）
- 环境：`npm run build && npm run start`，`npm run demo:reset` 后执行，视口 1440×900，演示模式，WebGL 由 SwiftShader 软件渲染
- 结果：**15 个检查点全部通过**（`docs/test-evidence/e2e-result.json`），截图 `docs/screenshots/01–12`

检查点：开场提问出现；花园模式场景与入口可见；档案显示种子；回答带“版本 + 页/段”引用；引用定位到资料片段；专注学习模式（宽阅读区 + 侧边小场景）；SQL 规则诊断；独立变式通过后开花；成长反馈卡片与“查看这次成长”；关键词 2 组 → 组合 1 组；定位原消息高亮；从原位置继续提问；刷新后恢复；概率统计植物开花；页面无运行时错误。

## 4. 性能观察（非性能承诺）

`npm run explain` 在模拟数据（2 万组问答、4 万条消息）上执行 EXPLAIN ANALYZE，结果与执行计划见 `docs/sql/explain-results.md`。测试过程中发现“关键词候选用 `IN (子查询)`”会被规划成嵌套循环（中文四字词约 1 秒），改为与候选集 JOIN 后同一查询约 20 ms——这一修改已进入代码。
