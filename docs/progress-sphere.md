### 实测限制（如实记录）

- 单圃容量 31 株（有本命花 27+1），超出计入 `overflow`，**分页/收起 UI 尚未实现**；

## 第七轮：触屏手势与双指缩放（2026-10-29 23:20）

> 第六轮的「下一轮建议」第 1 条。用触屏模拟把第一轮交付里唯一没验证过的交互补上。

### 现场

- 分支 `feature/b-visual`，从 HEAD `a32b129` 起步，工作区干净。
- 测试环境：Playwright（chromium + swiftshader），**390×844 / `is_mobile` / `has_touch`**；两指事件走 CDP `Input.dispatchTouchEvent`（Playwright 没有 pinch API）。脚本 `.dsh-tools/touch.py`（仓库外，不污染仓库）。
- 未登录访问 `/space` 是 307 跳转，脚本先 `POST /api/auth/demo` 拿会话（demo 账号，只读操作，未写用户数据）。

### 改前事实（实测，不是推测）

- 单指横向拖动：能环绕（前后两帧 35.9% 像素变化）。
- 单指纵向拖动：`touch-action: pan-y`，实测页面并不滚动（`scrollHeight 844 = innerHeight`），画面有变化，但纵向手势有被浏览器接管后 `pointercancel` 打断的隐患。
- **双指捏合：完全没有反应**。改前捏合前后天空占比 9.1% → 9.6%、地形 5.0% → 3.7%，只是空闲自转带来的位移，视距没变。

### 改动（`src/components/world/GardenWorld.tsx`）

1. 世界层 `touchAction: "pan-y" → "none"`：页面本身不需要滚动（实测 scrollHeight 等于视口），先把纵向手势留给俯仰，不再被浏览器抢走；
2. 多指跟踪：`pointers`（pointerId → 坐标）+ `pinch { d0, z0 }`。第二指落下即进入缩放并清掉单指环绕基准（否则第二指落下的瞬间视角会跳）；`zoom = z0 * d0 / d`，仍夹在 **0.75–2.2**；两指松开一指时，把剩下那根手指当新的环绕基准；
3. 抽出 `applyZoom()`，滚轮 / 键盘 / 双指共用同一套夹取逻辑；
4. 抬起、取消、离开统一走 `endPointer()`，避免手指被系统打断后残留按下状态。

### 验证（同一脚本、同一机位、改前/改后对比）

## 第十二轮：规模压测（draw / tri）与植物档案侧卡的 Esc（2026-10-30 00:15）

### 目标与验收方法

### 实测（同一台机器、同一场景、只有植物数量不同）

| 数据 | draw calls | 三角面 |
|---|---|---|
| n=10 / 1 个花圃 | **488** | 393,840 |

| n=100 / 3 个花圃 | **1,320** | 586,924 |

- 要达标只有两条路：把「每株 9–10 个 mesh」合并成 2–3 个（花瓣已合并，仍剩茎、叶、花托、hit 体、待复习小灯等），或对超出阈值的部分改成合并批次/静态贴花。这是下一轮的主要建模优化方向。
