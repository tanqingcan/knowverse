# 完整球体与可探索空间 · 进度记录

> 目标：把「只有正面球冠的布景」变成可环绕探索的完整星球。每轮记录分支/改动/证据/风险。

## 基线（轮 1 开始，2026-10-29）

- 分支 `feature/b-visual`，HEAD `ba6d9ad`，工作区干净；无 `AGENTS.md`。
- 站点 `http://127.0.0.1:3000` 可访问；PostgreSQL 5432 `accepting connections`（数据未动）。
- 现状核查：
  - 星球几何**已经是完整球体**（`planetGeometry()`：`SphereGeometry(3,160,120)` + 俯视平面 UV + 1024² 手绘地表）；
  - 但相机只允许绕 Y **±0.6 rad（±34°）**，看不到背面；
  - 草丛/野花只铺到 `d ≤ 2.35`（极角 ≤ 45°），外圈只有平面纹理；
  - 场景物体（花圃/建筑/树）集中在球冠，背面基本只有草。
- 基线性能：`/dev/garden?perf=1` **381 draw / 210k tri**（花瓣合并后）。

## 第三轮：花圃扩容与布局健壮性（2026-10-29 19:52）

### 复核现状

- `layoutBeds` 的环位容量：有本命花 27 个位置、无本命花 31 个位置；
- 超出容量的植物会取到不存在的槽位 → `x/z = undefined` → **床半径与植物坐标变 NaN**；
- 第 8 个及以后的花圃用旧兜底 `sin(i*2.4)*1.9`，与已有槽位**重叠**。

### 改动

| # | 内容 | 文件 |
|---|---|---|
| 1 | 环位容量上限 + 新增 `BedLayout.overflow`：超出部分**计数**而不是静默丢弃/NaN | `layout.ts` |
| 2 | 第 8 个及以后的花圃改用**黄金角螺旋**（`r ≤ 2.2`），不再和已有花圃挤在一起 | `layout.ts` |
| 3 | 纯函数单测（0/1/10/30/50/100 株 × 1/3/7/12 花圃 + 去重 + 稳定性 + 间距 + 范围） | `tests/unit/layout.test.ts` |
| 4 | 无数据库的测试配置（默认 `tests/global-setup.ts` 会重置 `knowverse_test`，本机没有该库） | `vitest.unit.config.ts` |
| 5 | `/dev/garden?n=100&g=3` 隔离压力数据（不碰真实账号） | `dev/garden/page.tsx` |

### 验证

- 修复前：28 例中 **4 例失败**（30/50/100 株单圃、100 株 3 圃，`b.r` 为 NaN）；
- 修复后：**28/28 通过**；`tsc --noEmit` 通过；
- 压力截图：`docs/screenshots/ui/sphere-stress100.jpg`（100 株 / 3 圃）。

### 实测限制（如实记录）

- 单圃容量 31 株（有本命花 27+1），超出计入 `overflow`，**分页/收起 UI 尚未实现**；
- 100 株 / 3 圃 时每圃接近容量上限，花圃半径变大，**彼此仍有重叠**；真实演示数据（13 株 / 2 圃）不受影响；
- 结论：**建议单圃 ≤ 30 株、花圃 ≤ 7 个**；超过需要做「花圃分页/分景」。
- 学科选择/搜索/按学科定位的 UI **本轮未做**（留到下一轮）。
