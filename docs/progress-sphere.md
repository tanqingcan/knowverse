# 完整球体与可探索空间 · 进度记录

> 目标：把「只有正面球冠的布景」变成可环绕探索的完整星球。每轮记录分支/改动/证据/风险。

## 基线（轮 1 开始，2026-10-29）

- 分支 `feature/b-visual`，HEAD `ba6d9ad`，工作区干净；无 `AGENTS.md`。
- 站点 `http://127.0.0.1:3000` 可访问；PostgreSQL 5432 `accepting connections`（数据未动）。
- 现状核查：
  - 星球几何**已经是完整球体**（`planetGeometry()`：`SphereGeometry(3,160,120)` + 俯视平面 UV + 1024² 手绘地表）；
  - 但相机只允许绕 Y **±0.6 rad（±34°）**，看不到背面；
  - 草丛/野花只铺到 `d ≤ 2.35`（极角 ≤ 45°），外圈只有平面纹理；
  - 场景物体（花圃/建筑/树）集中在球冠，背面基本只有草。
- 基线性能：`/dev/garden?perf=1` **381 draw / 210k tri**（花瓣合并后）。

### 与原 B2 的差异（需团队确认）

`docs/visual-redesign.md` 原文写「只允许有限拖动（±34°）、不会连续自转」，与本轮「全周探索」要求冲突。本轮按**新要求**实现，旧描述待更新；文档已在此处标注差异。

### 验证

- `tsc --noEmit` 通过；
- 拖拽四方位截图：`docs/screenshots/ui/sphere-{front,right,back,left}.jpg`，俯视：`sphere-top.jpg`；
- 键盘 → 旋转、滚轮 → 缩放、点「视角」→ 复位，均逐项截图确认（未留存全部，见临时目录）；
- 空闲自转：间隔 8 秒两张截图，整图平均差 **23/255**（明显旋转）；
- 四方位均能看到草/树/石头，无空洞、无破面；家具仍竖直，花草贴球面。

### 性能（同一台机器，SwiftShader）

- 改后：**461 draw / 293k tri**（+80 draw / +83k tri，主要来自外圈草与 16 处野生树丛）。
- 与 B5 的 120 draw 目标有距离；后续可把野生树丛实例化/降面，或按距离做 LOD。

### 风险与教训

- **编码事故**：用 PowerShell `Set-Content` 改 `GardenWorld.tsx` 时被写成非 UTF-8，导致 dev 编译失败；已用 `git checkout` 恢复并重做改动。后续修改一律用编辑工具，不用 shell 重写源码。
- 触屏**双指缩放**尚未实现（目前只有滚轮/键盘/按钮）。
- 平面 UV 在赤道附近有拉伸；俯仰到 `TILT_MIN` 仍看不到南极。

### 下一轮建议

1. 外侧/背面加 1–2 个「可探索目标」（观星台 / 种子小棚），让环绕有目的；
2. 野生树丛实例化，把 draw/tri 压回去；
3. 手机端双指缩放 + 触摸手势验证；
4. 花圃扩容（第二轮）。

### 验证

- `tsc --noEmit` 通过；
- 缩到最大后截图：整颗星球可见（`docs/screenshots/ui/sphere-full-front.jpg`），环绕 180° 后背面与观星台可见（`sphere-full-back.jpg`）；

- 性能：**470 draw / 293k tri**（观星台 +9 draw）。

### 本轮事故（重要）

- 又用 PowerShell `Get-Content -Raw` + `Set-Content` 改 `GardenWorld.tsx`：PS 5.1 默认按 ANSI 读、按 UTF-8 写 → 中文变 mojibake（按钮文字变成乱码）。
- 处理：`git checkout` 恢复到上一提交，再用**编辑工具**逐条重做（不丢上一轮成果），并确认文件无 BOM、中文正常。
- 结论：**源码一律用编辑工具修改**，shell 只做 git / 构建 / 截图。
