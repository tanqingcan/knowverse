# 3D 性能预算与实测（B5）

> 场景：`/dev/garden`（7 株植物 + 全部道具 + 512 丛草）。1440×900，Chrome headless + SwiftShader（软件渲染）。
> 探针：打开 `/dev/garden?perf=1`，左上角实时显示 `FPS · draw calls · 三角面`。

## 实测

| 指标 | 优化前 | 优化后（花瓣合并） | 建议预算 |
|---|---|---|---|
| draw calls | 435 | **381** | ≤ 120 |
| 三角面 | 211,454 | 210,194 | ≤ 120k |
| FPS（软件渲染） | 截图环境不可靠 | 同左 | ≥ 12 |

**已做**：玫瑰 / 向日葵 / 鸢尾的花瓣，从「每片一个 mesh」合并成「每株花 1 个 mesh」（`MergedPetals` + `mergeGeometries`），省了约 54 次 draw call，观感不变。

## 主要剩余开销

1. **叶片**：每种花 3–5 片，仍是独立 mesh。
2. **道具**：温室/书屋/树/长椅等由很多小 mesh 组成。
3. **阴影**：主光开了 1024² 阴影，阴影 pass 会再画一遍。
4. **草丛 / 野花**：已经实例化（各 1 次 draw），不是瓶颈。

## 优化方向（下一步）

- 叶片同样合并（预计再省 ~30 draw）。
- 道具按材质合并（温室木框、书屋等）。
- 阴影：只让主要物体投影，或降到 512²。
- 目标：draw calls ≤ 120、三角面 ≤ 120k、软件渲染 ≥ 12fps。

## 备注

- headless 的 FPS 采样受虚拟时间影响，截图里显示 `0 fps`；真实浏览器打开 `/dev/garden?perf=1` 可看到实时值。
- 探针只写 `#perf-hud` 文本，`perf` 默认 false，不进生产逻辑。
