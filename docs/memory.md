# C5 记忆系统

2026-11-11，提示词版本`chat-v1.5`。复用已有`memories`表与B的记忆面板，不另建`user_memories`。数据库扩展草案为`docs/sql/drafts/memory-system.sql`，本机已安装，正式Drizzle/schema与RLS仍需A集成。

## 长期记忆链路

当前用户消息 → 主模型调用`propose_memory`提议（只进入请求内队列，不写库）→ 若符合自述规则且没有提议，可额外调用一次模型提取 → 后端来源与内容检查 → 回答完成事务内保存 → 下一会话按相关性/重要度/新近度读取。

- content只接受当前用户原样连续自述，4–240字；来源必须是本人complete用户消息，ID由后端绑定，模型不能任意指定历史来源。至少置信度0.7，排除密码、Key等凭证。模型置信度只是规则输入，不是科学可靠性分数。
- 知识点必须公共或本人可见，且名称或别名出现在自述中；后端可自动匹配。
- 标准化内容的SHA-256作为去重键。相同用户/类别/内容合并并更新新近度、较高置信度/重要度与到期时间；不是语义相近句的自动合并，也不做无依据推断。
- per-user事务锁和唯一索引兜底并发重复写入。首次来源保持稳定，重复提及不覆盖首次来源。
- TTL由服务器决定：学习事实30天、偏好180天、近期事件7天。过期记录不返回、不注入；新来源明确再提及可重新记录。旧有演示记忆expires_at为空，保留兼容，不自动认定已过期。
- 读取先优先关联知识点，再按重要度/更新时间排序，最多5条，序列化UTF-8长度不超过1800字节；这是保守长度预算，不是精确tokenizer计数，也不代表整个模型提示词总预算；超出单条预算的超长修正内容可能不被注入，面板仍保留全文。

## 删除与修正

DELETE是软删除，保留来源和原因；PATCH将原记录标corrected并建立新记录，保留corrects_id和来源，修正内容以用户主动编辑为准。修正继承原到期时间。原文与修正内容不同是正常情况，来源表示这条记忆最初从哪里产生，并不声称原消息包含用户后来的修正。

删除/修正形成墓碑，自动提议不能从同一来源或相同标准化原文重新写回。墓碑是精确来源/内容规则，不是语义遗忘模型；换说法明确重新自述仍可能形成新记忆。

删除/修正会递增memory_controls.revision并清除该用户摘要；摘要写回时校验revision，避免较早快照覆盖失效状态。近期上下文排除已删除/修正记忆的来源消息及其直接回复。已发出的模型请求不能追溯撤回；原对话仍保存在历史中，可由用户明确检索，删除记忆不是删除聊天记录。其他历史消息的改写/间接提及不属于精确来源过滤的保证范围。

## 短期会话摘要

每6轮完整问答或未摘要内容累计6000字符时重写，保留近期若干消息。摘要采用带seq/role的原文摘录（每条最多120字符、总长1600字符），不额外调用大模型、不推断用户事实。model_call_id指向触发摘要的聊天调用，method明确为extractive-v1，不把它冒充模型生成摘要。

读取摘要后，补上upto_seq之后最多20条近期消息，避免固定窗口与摘要之间漏掉对话。记忆来源及直接回复不写入摘要，个人学习自述通过可管理的长期记忆提供；修正/删除后摘要失效。长篇细节可能被截断，摘要不是完整历史替代物。

## 网页体验

1. 对话中输入“请记住：我一直搞不懂 LEFT JOIN，尤其是 ON 和 WHERE 的区别。”
2. 打开记忆面板，检查原文与来源链接。
3. 新建会话问“我今天想复习连接查询，你建议从哪里开始？”，观察是否结合难点。
4. 在记忆面板删除该条，再新建会话问“只根据当前memory列出我的长期学习记忆，不检索历史”。
5. 保存一条解释偏好，在面板修正后，新建会话提问验证新版偏好。模型回答有随机性，以面板及后台上下文轨迹为准。

本轮没有控制浏览器逐项验收；已验证真实服务层及数据库持久化。

## 安装与交接

`npm run memory:install`只允许本机，安装增量SQL草案，不删除旧数据；未安装时保留原记忆列表/修正/删除接口，关闭自动记忆和摘要。`npm run eval:memory`创建独立禁用登录评测账号，运行5次真实对话，保留来源和结果，会产生API调用费用。

A需把新增列、唯一索引、memory_controls与conversation_summaries纳入正式schema和迁移，并审查source_message_id/user_id、conversation_id/user_id的数据库归属约束与应用角色/RLS。当前代码应用层隔离不等于数据库RLS，未宣称A1已完成。B可继续复用GET/DELETE/PATCH现有契约，无需替换面板；D需把安装草案纳入新克隆/演示环境准备。
