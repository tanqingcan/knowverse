# R17 拾取误差：从 30.79px 修到 0.0px

> 状态：**双轮通过**

## 一、研究
- **three.js 官方示例 `misc_controls_pointerlock` / `webgl_interactive_cubes`（MIT）**：拾取与放置必须共用**同一个几何体**做 intersect；若"拾取用一个代理几何、渲染用另一个"，两者的表面点会系统性偏移。
- **球面 vs 平面**：平面案例里代理是 `PlaneGeometry`，其顶点共面、误差只在边界；球面代理若是**低分段多面体**，`e.point` 落在**三角面**上，其"从球心出发的方向"与理想射线方向差可达半个面角（本项目拾取球是 `sphereGeo(3.12, 24, 16)` → 方位 15°/面、俯仰 11.25°/面 → 半面角 7.5° / 5.6°）。这正是平面案例不会暴露、球面必然暴露的差异。

## 二、第一遍实现
- 新增探针 `window.__gardenProject(cap)`：用真实相机把球冠坐标投影成屏幕 CSS 像素，用于量化"目标点 vs 最终锚点"的误差。
- 第一遍只测量、未修：点击 (760,520) → 锚点投影 (757.7,550.7)，误差 **30.79px**。

## 三、审查（第一遍真实失败）
1. **[高] 误差 30.79px，远超 ≤8px**。
2. **[高] 我自己的探针第一次写错作用域**（`__gardenZoom = zoom` 插在 Canvas 内）→ `TS2304`，整页编译失败。
3. **[中] 诊断一度走错方向**：先怀疑 `pointToCap` 公式错，用 Python 复刻三个函数做纯数学往返——结果**完全互逆**（(0.3,0.3)→world→(0.3,0.3)），排除了公式问题，才转向"拾取几何"。
4. **[高] 定位到根因**：放置拾取层是 `sphereGeo(3.12, 24, 16)` 的**低模球**，`onPointerMove`/`onPointerUp` 都用 `pointToCap(e.point)`——`e.point` 在三角面上，方向偏半个面角（实测方位偏 10.6°、俯仰偏 1.3°，正好是低模球的半面角量级）。
5. **[中] 旁证**：R18 用同探针点选"小屋/树/玫瑰"时**每次都选中旁边的「灌木」** → 系统性错位，不是随机抖动。

## 四、第二遍实现
- 新增 `rayToCap(ray, fallbackPoint)`：**优先用射线与理想球（`PLANET_R`）求交**再换算球冠坐标，不再使用低模代理的 `e.point`；取不到交点时才回退 `e.point`。
- ghost 跟随（预览）与点击确认（落位）两处都换成 `rayToCap(e.ray, e.point)`。
- 保留 3.12 的代理球作为"更大的点击热区"，但**坐标只从射线算**。
