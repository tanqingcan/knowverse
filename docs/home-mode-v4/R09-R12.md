# R09 两次点击移动 / R10 地形交点 / R11 单步撤销 / R12 暂停慢转

> 状态：R09 **双轮通过** · R11 **双轮通过** · R10 **第一遍待审**（无效落点提示已验；「点对象取背后地形」修复未实测）· R12 **第一遍待审**（paused 已覆盖创造/浮窗/DIY，相机手势与「拖空白不确认」未单独实测）

## 一、研究
- 复用 V3 已读 **three.js `Editor`（MIT）**：`TransformControls` 拖拽期间相机禁用，且**一次变换产生一条 `SetPositionCommand`**（而不是每次 pointermove 一条）——本项目原来在 pointermove 里连续 `update`，正是"几十个 undo"的来源。
- **球面 vs 平面**：three Editor 的平面拖拽直接用 `plane.intersectRay`；本项目必须与**球面**求交（`pointerToCap` 已是相机射线 × 球），否则在旋转后的镜头上会漂移。

## 二、第一遍实现
- 移除"指针按下即拖动"：`DecorItem` 的 `onPointerDown` 不再 `decorDrag.current = id`（对象默认不再被拖）。
- 新增移动模式：选中对象 → 点「移动」（或按 **M**）→ 指针在星球上移动只显示半透明 ghost → **点击地面确认**；Esc 取消；原对象在确认前保持原位。
- 确认时才调用一次 `decorStore.update(id, {x,z})`；预览全程不写 store、不写 DB。
- R10：落点无效（点天空）→ 热栏提示「这里放不了：请点击星球表面」。
- R12：`paused` 覆盖创造模式/浮窗/开场动画，再补 `diyTarget`（DIY 工作台打开时也暂停慢转）。

## 三、审查（第一遍真实失败）
1. **[高] 默认拖动仍在**：`onPointerDown` 里 `decorDrag.current = d.id` → 按住对象移动即改坐标，与 R09 冲突（用户反馈的"对象默认拖动"）。已删。
2. **[高] 拖动期间每次 pointermove 都 `update`** → 产生大量 undo 步。改为只在新路径确认时更新一次；旧 `onDecorMove` 保留但拖动入口已关闭。
3. **[高] 预览 ghost 用的参数是「素材默认值」**（`{kind, rot:0, scale:1}`），移动时会丢掉原对象的旋转/缩放/配色 → 确认前后不一致。改为移动模式下用**被移动对象自身参数**。
4. **[中] 落点无效无反馈**：点天空什么都没发生。
5. **[中] 点对象表面会把"对象表面点"当落点**（R10 明确禁止），需改成该射线与球面的交点（背后地形）。
6. **[中] 我自己的测试脚本 KIND 映射漏了「观测台」** → 读到错误对象坐标，第一次跑出"位置没变"的假阴性。

## 四、第二遍实现
- 修 1/2/3：删拖动入口；预览参数改为对象自身；确认才写一次。
- 修 4：`onPointerMissed` → `onPlaceMiss` → 热栏提示。
- 修 5：对象 `onPointerUp` 在放置/移动状态下先取 `e.ray` 与球面交点再确认。
- 修 6：测试 KIND 映射补齐。
