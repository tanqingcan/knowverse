# R02 槽位多入口进替换 + 空槽 / Esc 语义

> 状态：**双轮通过**

## 一、研究
- 复用 R01 的研究（three Editor 的「选择≠执行」信号分离、Minecraft 式槽位/物品库分离）。本轮补充：**触摸设备没有右键**，所以必须提供「长按」与「键盘 Enter」两个等价入口；这是"多入口同一动作"的常见做法（原生 `contextmenu` + `setTimeout` 长按）。
- 未采用长按库（如 Hammer.js）：一个 500ms `setTimeout` 足够，避免新增依赖。

## 二、第一遍实现
- 槽位 `onContextMenu` → `onEditSlot(i)`（右键）。
- 槽位主按钮 `hb-main` 是原生 `<button>`，键盘聚焦后 **Enter/Space 天然触发** `onEditSlot(i)`（不需要额外 keydown）。
- 空槽：`onEditSlot` 对任意索引都生效，`hb-place` 只在有素材时渲染。
- Esc：库 `onClose` 只 `setLibOpen(false); setSlotEdit(null)`，**不写 hotbar**；替换态下不做任何场景实例创建。

## 三、审查（第一遍后实际失败）
1. **[中] 长按缺失**：第一遍只有右键 + Enter，触摸设备（无右键）无法进替换 —— 这正是 R02 明写的要求。
2. **[中] 空槽未验证**：逻辑上 `onEditSlot` 对所有索引生效，但没有实测"清空后点击".
3. **[低] 长按与点击的竞态**：长按 500ms 触发后松手会再触发一次 click（重复调用 `onEditSlot`，幂等但会重复打开库）。

## 四、第二遍实现
- 槽位加 `onPointerDown` 500ms `setTimeout` → `onEditSlot(i)`；`onPointerUp` / `onPointerLeave` 清理（`lp` ref）。
- 竞态：`onEditSlot` 是幂等设置（同一个 slotEdit + 已开的库），重复触发不会产生额外实例或重复关闭，实测无异常。

## 五、复审（真实操作）
```
R02 Esc → 库关闭: True | 槽位不变: True
R02 右键槽3 → 库: True | 提示: 替换第 3 槽 · 原「开花小树」 → 待选
R02 长按槽4 → 库: True | 提示: 替换第 4 槽 · 原「灌木」 → 待选
R02 聚焦后 Enter → 库: True | 提示: 替换第 5 槽 · 原「木栅栏」 → 待选
清空槽按钮: True | 清空库后槽6: 空
R02 空槽点击 → 提示: 替换第 6 槽 · 原「空槽」 → 待选 | 库开: True
pageerrors: []
```
- 四个入口（点击/右键/长按/Enter）都进同一替换流程；空槽点开显示「原「空槽」」；Esc 后槽位不变。
- 结论：**双轮通过**。
