# R07 槽配置与布局存储分离 / 按账号 / 坏配置回退

> 状态：**双轮通过**

## 一、研究
- 复用 three.js `Editor`（MIT）的 **`Storage`/`Config` 分层**思路：编辑器把"界面偏好（面板宽度、相机速度）"与"场景文档"分开存，前者是本地偏好、后者是工程文件；二者生命周期不同，不能共用同一个键。
- **未采用**任何第三方状态库：本项目只需"把本地偏好按账号分桶"，`localStorage` 前缀 + 账号 id 足够，新增依赖无收益。

## 二、第一遍实现（读代码定位）
- 现状：`HOTBAR_KEY = "kv-hotbar"`（**全局键**），保存与读取都不带账号 —— 同一浏览器换账号会读到上一个人的 9 个槽。
- 现状：坏配置走 `catch { /* 忽略 */ }`，**静默回默认、无任何提示**。
- 改动：
  - 键改为 `kv-hotbar:<userId>`（未登录用 `kv-hotbar:anon`）。
  - 读取时区分三种情况：合法 → 用；**非法 → 回默认 + 提示「快捷栏配置已损坏，已恢复默认（旧数据保留在本地）」**；读取异常 → 回默认 + 提示「快捷栏配置读取失败」。
  - **旧版全局键一次性迁移**：当前账号键不存在且旧键存在时迁移，并提示「已把旧版快捷栏配置迁移到当前账号」；旧键 JSON 也坏时另存 `...:legacy-broken` 不丢数据。
  - 写回只跟随 `hotbar` 变化，键用 `ref` —— **账号切换瞬间不会把上个账号的槽位写进新键**。

## 三、审查（第一遍真实失败）
1. **[高] 全局键导致串槽**：改前 `kv-hotbar` 无账号维度，是 R07 明确禁止的"账号切换串槽"。
2. **[高] 坏配置静默回退**：`catch {}` + 无提示，用户会以为自己的快捷栏"自己变回去了"。
3. **[中] 我自己的测试脚本 bug #1**：reload 后没重新进创造模式，读到 `hb-slot` 数量 0 → 误判"刷新后为空"。
4. **[中] 我自己的测试脚本 bug #2**：迁移用例用 `Object.keys().find()` 删了 `kv-hotbar:anon` 而不是账号键，导致迁移分支根本没触发。

## 四、第二遍实现
- 修 #1/#2 如上（按账号键 + 三态提示 + 迁移）。
- 修 #3：测试在每次 reload 后重新点「创造」。
- 修 #4：改为先列出所有 `kv-hotbar*` 键再按前缀删除。
- **写回守卫**：`hotbarReady` + `hotbarKeyRef`，避免"账号切换时把旧账号槽位写到新键"这个隐蔽串槽路径。

- 配置键（`kv-hotbar:<uid>`）与布局存储（`kv-decor` / 服务端 `planet_layout_items`）**互不引用**；换账号读的是不同键，不会串槽。
