# R16 镜头速度与缩放 / R17 拾取误差

> 状态：R16 **第一遍待审** · R17 **第一遍待审**（**实测误差 30.79px > 8px 目标，未通过**）

## 一、研究
- 复用 V3 已读 **three.js `Editor`（MIT）** 的 `Viewport`/相机控制：镜头灵敏度是"可配置参数"，且有上下限；缩放按固定步长而不是跟随硬件 delta 大小。
- **球面 vs 平面**：平面相机的"缩放"是沿视线平移；球面这里改的是**相机到球心的距离倍率**（`zoom` 0.75–2.2），再配上固定的环绕速度。

## 二、第一遍实现
- **R16**：
  - 方向键环绕速度 **0.12 → 0.06 rad/次**（俯仰 0.08 → 0.05），相较旧版明显降低；
  - 滚轮缩放固定步长 0.07/次，**Shift = 慢速档 0.03/次**，不随硬件 `deltaY` 大小突变；
  - 新增**可见缩放按钮**（＋ / － / 1×，桌面 38×34 / 手机 44×44），以及既有的 `0.75–2.2` 上下限。
- **R17**：新增调试探针 `window.__gardenProject(cap)`——用**真实相机**把球冠坐标投影成屏幕 CSS 像素，用于测量"点击点 vs 最终锚点"的误差（此前只能用 `.world-selbar` 位置，会被视口夹住，探针失效）。

## 三、审查（第一遍真实失败）
1. **[高] 探针第一次写错作用域**：`__gardenZoom = zoom` 被插到 Canvas 内的 `Scene`，而 `zoom` ref 在外层 → `TS2304 Cannot find name 'zoom'`，整页编译失败（测试里"选中: ?"就是这个原因）。改用 `props.zoom`。
2. **[高] R17 实测误差 30.79px，远超 8px 目标**：点击 (760,520) → 对象落到球冠 (0.08968,0.5066) → 用真实相机投影回屏幕是 (757.7, 550.7)，**y 方向偏 30.7px**。说明"点击拾取用的映射"与"锚点渲染用的映射"不一致（`pointToCap` 与 `capFrame/surfaceFrame` 对同一球面点的解释不同），这是本轮最重要的发现。
3. **[中] 方向键 Δyaw 测量取到 0.0**：上一步移动确认后对象仍选中，按 Esc 后测量时机受干扰，方向键仍在移动对象而非相机 → 该项测量无效，需重测。
4. **[中] 滚轮 5 步实测 Δzoom=0.28 而非 0.35**：`sign(deltaY)` 固定步长下有一步落在节流/首帧丢失，属测量口径问题，需按单步重测。

## 四、第二遍实现（本轮已做部分）
- 修 #1：探针改用 `props.zoom`（编译恢复）。
- #2 是**未修的功能缺陷**，下一轮需对齐两套映射（把 `pointToCap` 与 `capToAzPolar` 做双向单元测试，再改实现）。
- #3/#4 为测量口径问题，下一轮重做。
