# R15 四向微移按钮 + 数值精确输入（球面坐标）

> 状态：**双轮通过**

## 一、研究
- 复用 V3 已读 **three.js `Editor`（MIT）** 的属性面板：数值输入是"受控但允许中间态"的输入（用户输 "0." 时不能立刻把值写成 0）。原生 `input[type=number]` + 受控 `value` 的经典坑就是**每击键都 parse 并回写**，导致输入被打断。
- 球面 vs 平面：本项目的"位置"是**球冠平面坐标（x,z）**，不是世界 XYZ —— 必须在界面上显式说明，否则用户会以为是世界坐标。

## 二、第一遍实现
- 选中对象 → 点「移动」→ 属性浮层里新增：
  - **四向 D-pad**（↑←→↓ 四个按钮，桌面 40px / 手机 44px），点击走与方向键同一条 `nudgeRef`（相机屏幕方向 → 球面切平面）；
  - 步长提示「步长 0.015（Shift 精调 · Alt 粗调）」；
  - 说明文字「下面是**球面（球冠）坐标**，不是世界 XYZ」；
  - 球面 X / 球面 Z 数字输入；角度/比例也改数字输入。

## 三、审查（第一遍真实失败）
1. **[高] 受控数字输入在真实键盘输入下会被打断**：先只写 `value={+selItem.x.toFixed(3)}` + 每次 `onChange` 就 commit。用户输 "0.77" 时中间态 "0." → `+"0."` = 0 → 立刻回写 0 → 后面再敲的字被吞。这是**键盘输入可用性**问题，不是样式问题。
2. **[中] 角度/比例仍是滑杆**：R15 要求"位置/方向/尺寸可精确修改"，滑杆无法精确输入。
3. **[中] 没有说明"球面坐标"**：用户会按世界 XYZ 理解。
4. **[低] D-pad 没有 Shift/Alt 修饰**：与键盘步长不一致。

## 四、第二遍实现
- 修 #1：新增模块级 `NumField` 组件——本地 `text` 状态 + 提交守卫（`raw === ""` / 以 "." 或 "-" 结尾时不提交）+ `onBlur` 校正 + `useEffect` 跟随外部值。
- 修 #2：角度/比例改用 `NumField`（min/max/step 各自设定）。
- 修 #3：加 `.sel-coord-note` 说明。
- 修 #4：D-pad 按钮读取 `e.shiftKey` / `e.altKey` 决定 0.001R / 0.005R / 0.02R。

## 五、复审（真实浏览器，含真实键盘输入）

- 四向按钮真实可点、方向正确、不动相机；数值输入**逐字键入不跳值**，最终精确生效。
