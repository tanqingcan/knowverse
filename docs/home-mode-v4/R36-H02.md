## 三、三类根因

1. **[已修] 氛围光晕精灵可被拾取**：`GardenWorld.tsx` 有两处 `<sprite>`——
   - 第 486 行：9 个 `visible={false}` 的 halo 精灵（three 的 `Raycaster` **不检查 `visible`**，仍然参与求交）
   - 第 953 行：22×9 的背景光晕
   修复：两处都加 `raycast={() => null}`。修复后暖光书屋的命中从"精灵+路灯"变为**只有路灯**。
2. **[真几何遮挡] 路灯挡住书屋**：这是真实场景布局问题（路灯在相机与书屋之间），不是拾取 bug。用户点那里确实先碰到路灯——可以接受，但意味着"点建筑"要挑没有被遮挡的角度。
3. **[待查] 第三个 Sprite**：资料温室的屏幕点仍被 `Sprite@6.21` 挡住。已 grep 出 `Sprite` 只在 3 处出现（470/471/486 + 953），前两处已禁用拾取，说明还有别的来源（可能是 `PlantNode`/`Bed` 里的 sprite，或 three 内部生成的）。

## 七、但点击选中仍失败（新发现）

### 候选原因（下一轮逐一排除）
1. `DecorItem` 的 `onPointerUp` 里 `e.delta < 6` 判定：Playwright 的 click 由独立 down/up 组成，若 R3F 计算的 delta 超阈值就会被吞
2. `onPointerUp` 里 `e.stopPropagation()` 与 `.world` 的相机拖拽 handler 顺序冲突
3. 装饰根组没有 `name`，R3F 的事件对象绑定在子 mesh 上，而 `props.onDecorSelect(d.id)` 需要从事件冒泡链拿到 `d`
4. `props.readOnly` / `props.mode` 在创造模式下的取值

## 九、第三层定位：R3F 事件系统未派发（本轮新增）

### 三层证据链

| 层 | 验证方式 | 结果 |
|---|---|---|
| 1. 射线拾取 | `__gardenPick(x,y)`（真实相机 + Raycaster） | **5/5 命中建筑自身 mesh** ✅ |
| 2. DOM 事件 | `canvas.addEventListener('pointerdown'/'pointerup')` | **都收到了**（`pointerdown@CANVAS`, `pointerup@CANVAS`）✅ |
| 3. R3F 回调 | `onPointerUp` 内的 `console.log` + `.world-selbar` 数量 | **一条日志都没有、selbar=0** ❌ |

### 已排除的原因
- `editing={creativeOpen}` — 接线正确（SpaceApp:665）
- `props.mode === "garden"` — 创造模式成立
- `e.delta >= 6` — down/up 同坐标，delta=0
- `props.readOnly` — false
- 精灵遮挡 — 三处已修，pick 5/5 命中建筑

### 结论
**R3F 的 `onPointerUp` 没有派发到 `DecorItem` 的 group 上**，尽管原生 pointerup 已到达 canvas、射线也能命中。
嫌疑：`<OnCap name=...>` 包裹层级 + `register()` 名称注册 + R3F 的 `eventObject` 冒泡链相互作用，
或 `onPointerDown` 里的 `e.stopPropagation()` 破坏了 R3F 的按压状态机（down 被吞 → up 不再派发）。

### 下一步（优先级）
1. 临时移除 `onPointerDown` 的 `e.stopPropagation()` 看 up 是否恢复
2. 检查 `<OnCap>` 是否给子 group 设了 `raycast={null}` 或类似
3. 用 R3F 的 `onPointerMissed` 验证事件系统是否整体失效（vs 仅该对象）

## 十一、lift 扫掠与 flaky 证据（本轮）

### 方法
对 5 栋建筑 × 15 档 lift（0.02–0.30），每档 click 后读 `.selbar-name`。

### 结果
```
种子小棚: lift=0.02 → 选中「种子小棚」✓
暖光书屋: FAIL（15 档全失败）   ← 但上一轮 lift=0.06 时通过过
资料温室: FAIL（15 档全失败）   ← 同上
观测台:   FAIL（15 档全失败）
花园拱门: FAIL（15 档全失败）
```

### 关键发现：**flaky**
- 上一轮（`v4-r34b`）：暖光书屋 ✓、资料温室 ✓（2/5）
- 本轮（lift 扫掠）：种子小棚 ✓，暖光/温室反而失败（1/5）
- 两次是**独立浏览器上下文**、同样的投影函数、同样的点击方式

**同一对象在不同运行中结果不同** → 不是"参数标定"问题，而是**点击选中存在偶发失败**。

### 已排除
- 精灵遮挡（pick 恒 5/5）
- `stopPropagation`（移除后仍 0/5）
- `editing`/`mode`/`delta`/`readOnly`

### 剩余嫌疑
- **R3F 事件与 DOM 事件的时序**：Playwright 的 down/up 间隔极短（<10ms），R3F 的 pointerdown→pointerup 状态机可能需要更长间隔或多帧
- **场景仍在加载/重建**：每次 Escape/点击都可能触发 re-render，事件绑定时机不一致
- **相机/动画帧**：`paused` 状态下 rAF 仍在跑，点击瞬间的相机矩阵可能与投影时微差

### 下一轮验证方向
1. **拉长 down→up 间隔**（如 200ms）重测，看是否稳定
2. 点击前等待 `requestAnimationFrame` 两帧，确保渲染稳定
3. 若确认是时序：这是**测试方法与交互设计的双重问题**（真实用户点击间隔远大于脚本）

### 现在的诚实状态
H02 = **部分通过（flaky）**。已通过的三栋（暖光书屋/资料温室/种子小棚）在不同轮次各自成功过，但没有一次运行里全部通过。不判通过。
