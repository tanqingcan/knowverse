# R13 方向键移动对象（屏幕方向投影到球面切平面）

> 状态：**双轮通过**

## 一、研究
- 复用 **drei TransformControls（MIT）** 的核心结论：变换手势必须与相机手势互斥。
- **球面 vs 平面**：平面编辑器直接加世界 XYZ 偏置；球面必须把"相机的屏幕上下左右"**投影到该点切平面**，再沿大圆走一小步，否则镜头一转方向就反。新增 `worldToCap()`（`capToAzPolar` 的逆）把切平面位移写回球冠坐标。

## 二、第一遍实现
- 定位 `GardenWorld.tsx` 方向键直接改 `drag.current = {yaw,tilt}`（改相机）。
- 改为：有选中对象时移动对象（`onDecorUpdate`），无选中才转相机；步长 `Alt=0.02R / Shift=0.001R / 默认=0.005R`；`e.repeat` 100ms 节流；`preventDefault` 防滚页。

## 三、审查（第一遍真实失败）
1. **[高] 直接引用 `camera`，但键盘 effect 在 Canvas 外层组件** → `TS2304`。
2. **[高] effect deps 只有 `[props.mode]`** → `selectedDecorId`/`decor` 闭包过期。
3. **[中] 极点切平面基退化未保护**。
4. **[中，测量问题] 第一版旋转用例是假失败**：转 90° 后去点原对象，它已转到**球背面被星球遮挡**，所以选中失败；此时按方向键走的是**相机分支**，屏幕 dx=-4.6 其实是相机转动导致的对象屏幕位移，不是"方向反了"。**修正审计方法**：转镜头后先网格扫描选一个**当前可见**的对象再测。

## 四、第二遍实现
- `nudgeRef` 由 `Scene` 用真实相机基注入（`capFrame`→相机矩阵第 0/1 列→投影到切平面→`worldToCap`）。
- `selIdRef`/`decorRef` 同步；退化返回 `null` 保持原位。
- 审计方法修订：转镜头后用扫描选当前可见对象。

## 五、复审（真实浏览器，四组）
```
A 未转镜头   选中 资料温室 → ArrowRight dx = +4.7   moved=True
B 转 90°(yaw=1.66)  选中 暖光书屋 → ArrowRight dx = +4.7   moved=True
C 转180°(yaw=3.22)  选中 路灯     → ArrowRight dx = +5.3   moved=True
D 极点(俯仰上限)    选中 小池塘   → 坐标 (0,2.24)→(0.01649,2.23998) 有限=True
pageerrors: []
```
- **三种镜头朝向（0°/90°/180°）下，方向键都让对象在屏幕上向右移动**；极点处不退化为 NaN。
- 结论：**双轮通过**。证据：`.dsh-tools/v4-r13c-test.py`、`v4-r13c-result.json`。
