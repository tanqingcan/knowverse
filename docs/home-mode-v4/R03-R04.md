# R03 全部建筑可入任意槽 / R04 重复素材按索引

> R03 状态：**双轮通过** · R04 状态：**双轮通过**（R04 的"选中边框与放置素材一致"只做了索引与提示条验证，边框视觉未截图对比，见审查 #2）

## 一、研究
- 复用 R01/R02 的参考。R03 的关键是**不能用固定允许列表过滤素材**：本项目素材来源是 `SCENE_ASSETS`（57 项）→ `PLACEABLE_ASSETS`/目录；只要目录里有的都应可入槽。已在 V3 的 `home-catalog.test.ts` 里验过"建筑全可编辑"，本轮验"建筑全可入槽"。
- R04 的关键是**索引而非 kind 查找**：`hotbar.indexOf(kind)` 遇到同 kind 多槽只会返回第一个，这是常见坑（Vue/React 列表 key 同源问题）。

## 二、第一遍实现
- 槽位渲染 `slots.map((kind,i))`，`key={kind}-${i}`；主点击 `onEditSlot(i)` → `setActiveSlot(i)`（**索引**）。
- 库内点素材 → `setHotbar(prev => prev.map((v,i) => i === target ? k : v))`，`target = slotEdit ?? activeSlot`（索引来源，不经过 `indexOf`）。
- 旧的 `onPick`（`hotbar.indexOf(k)`）保留但已不被任何点击使用。

## 三、审查（实际发现）

2. **[中] 重复槽的边框视觉未取证**：R04 要求"焦点、选中边框和放置素材一致"，本轮只验证了**索引正确**（第1槽/第9槽都显示"替换第 1 槽 / 第 9 槽"），没有截图对比边框。留作 R04 的补证项。
3. **[低] 槽位 key 用 `kind-i`**：同 kind 交换位置时 key 仍唯一（含索引），不会复用错 DOM。
