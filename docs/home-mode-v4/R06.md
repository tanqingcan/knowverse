# R06 980px 及三档宽度的竖排/截断/溢出；缩略图可辨认；移动端横滑不拦画布

> 状态：**双轮通过**

## 一、研究
- 竖排根因是 **flex 挤压导致中文逐字换行**（CSS 里没有 `word-break` 也会在显式宽度内逐字断），标准修法是 `min-width: max-content` + `white-space: nowrap`，而不是改字号。
- 缩略图可辨认：参考 three.js Editor 的资产面板用**真实缩略渲染**而不是色块；本项目没有离屏渲染缩略图的预算，改用"花卉真实 SVG + 建筑字符图形"折中（未采用“每个资产离屏渲一张 PNG”，因为要在创造模式初始化 21 个离屏 canvas，与 H55 的资源约束冲突）。
- 移动端横滑：`overscroll-behavior` + `touch-action: pan-x`（V3 H24 已做），本轮复查不拦画布。

## 二、第一遍实现
- 全局扫描脚本在 980/1440 找到唯一竖排元素：`.cp-title`（43×87）。
- 补 `white-space: nowrap` 到 `.hb-name/.hb-lib/.hb-mini`。

## 三、审查（实际失败）
1. **[高] 只加 `nowrap` 不够**：第一次只写 `white-space: nowrap`，标题仍被 flex 压到 43px 宽（nowrap 下 box 仍可被压缩，内容溢出到盒子外）。必须同时 `flex: 0 0 auto` + `min-width: max-content`。
2. **[中] 旧媒体查询可能反向覆盖**：`@media (max-width:860px)` 里旧 `.creative-palette` 规则还在，需要在同一断点重生明宽度。
3. **[低] 390 宽度下瓦片 109px**：每行 3 个，可接受；未再收窄。

## 四、第二遍实现
- 按 #1 补 `flex:0 0 auto` + `min-width:max-content`（修复后标题 64×20）。
- 按 #2 在同一 `@media (max-width:860px)` 里重声明 `.creative-palette/.layout-menu` 宽度与网格最小宽度。

## 五、复审（四档实测）
```
[980]  titleRect {w:64,h:20}  verticalTexts []  overflowX false  bodyScroll {sh:1024, ch:428}
[768]  titleRect {w:64,h:20}  verticalTexts []  overflowX false  bodyScroll {sh:1024, ch:607}
[1440] titleRect {w:64,h:20}  verticalTexts []  overflowX false  bodyScroll {sh:1024, ch:428}
[390]  titleRect {w:64,h:20}  verticalTexts []  overflowX false  bodyScroll {sh:1306, ch:466}
```
- 四档**竖排 0、横向溢出 0**、主体均内部滚动、头部/底部固定可见。
- 缩略图 44×44（花卉真实 SVG + 建筑字符图形），vision 复核"能看出具体物件"。
- 移动端：快捷栏 `touch-action: pan-x` 横滑（H24 已验 48×56 ≥44px）；触摸进替换有长按（R02）。
- 结论：**双轮通过**。证据：`.dsh-tools/v4-r06-test.py`、`v4-r06-result.json`、`v4-r06-980.png` / `v4-r06-768.png` / `v4-r06-1440.png` / `v4-r06-390.png`。
