# R19 花圃成为独立布局对象 / R20 移动时整圃同行

> 状态：R19 **第一遍待审**（选中+平移+植物随行已实测；选中框视觉与"稳定实例ID"未完成）
> 状态：R20 **第一遍待审**（植物随花圃移动已目视确认；围栏/木牌/点击锚点未验证）

## 一、研究
- **three.js `Editor`（MIT）** 的 `Group` 变换：把一组对象整体平移，最稳的做法是**改 Group 的 transform**，子对象的局部坐标不动 —— 这样"植物跟着花圃走"是自动的，不需要逐株改坐标。
- **球面 vs 平面**：平面的 Group 平移是 `position += delta`；本项目花圃组必须重新 `capFrame(x,z,rot)` 贴回球面（引入 `rot` 让整圃朝向可调）。

## 二、第一遍实现
- `bedLayout.ts`：`layoutBeds(gardens, plants, moves?)` 支持**按花圃索引覆盖位置/朝向**，`BedLayout` 新增 `rot`；未设置时仍用默认槽位（不改变已有布局）。
- `Bed` 组件：组 transform 用 `capFrame(bed.x, bed.z, bed.rot)`；**土壤面**加 `onPointerUp` → `onBedSelect(bed.index)`（点花圃边界选中整圃，不是点花 → 点单株植物仍是植物档案）。
- `GardenWorld`：透传 `bedMoves / onSelectBed / selectedBedIndex / bedMoving`；落位拾取球在**平移花圃时也挂载**（否则点地面不会触发确认）。
- `SpaceApp`：`bedMoves` 状态 + `bedSel`；M 键在选中花圃时平移整圃；`onPlace` 增加 `bed:` 前缀分支写入 `bedMoves`。

## 三、审查（第一遍真实失败）
1. **[高] 点目标没确认**：移动花圃时 `placingKind` 为 null，而"点击球面确认"的不可见拾取球是 `{props.placingKind && <mesh/>}` → **根本不挂载**，点地面没有任何反应。修：条件改为 `(props.placingKind || props.bedMoving)`，并给 ghost 跟随加 `placingPreview` 空保护。
2. **[中] `Bed` 的 props 类型不接受 `onBedSelect`**（它是 `Omit<PlantNode props>`）→ TS2322。修：在 Bed 的 props 加 `onBedSelect?`。
3. **[中] 选中后没有视觉选中框**：只给了热栏文案「已选中花圃「X」」，R19 要求"整体选中框和名称" —— **名称有了、框还没有**（未完成）。
4. **[中] "稳定gardenId/布局实例ID"未达成**：当前 `bedMoves` 的键是**花圃索引**，不是 DB 的 garden id；索引会随花圃排序变化。
