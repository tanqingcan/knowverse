# 课堂展示脚本

> 所有步骤对应真实功能。演示前运行 `npm run demo:reset` 恢复演示账号的初始状态（会删除并重建 demo / xingye / ahe 三个演示账号及其数据；课程目录与公共资料保留）。
> 演示账号：`demo / knowverse`（小屿）。预置历史在界面上标注“预置”；回答标注“演示回答 / 演示模式”。若配置了真实模型，回答会显示模型名。

## 演示前检查（1 分钟）

1. `npm run demo:reset`，然后 `npm run start`（或 `npm run dev`）。
2. 浏览器打开 http://localhost:3000 ，窗口建议 1440×900 或更大；投影仪性能较弱时在“设置”中选择“静态绘本（SVG）”。
3. 确认右上角显示“演示模式”或“真实模式 · 模型名”。

## 一、三分钟核心版（覆盖全部必选功能 + 视觉亮点）

| 时间 | 操作 | 讲解要点 |
|---|---|---|
| 0:00 | 打开首页，等待星空中的小星球靠近；出现问题“如果你有一颗自己的星球，你想在上面种下什么？”。点 **以演示账号进入** | 知屿把每个学习者表示为一颗星球；学科是花圃，知识点是植物 |
| 0:20 | 花园首屏：镜头靠近星球，书屋亮灯；左上是今日建议，底部是场景入口，左下是最近一次成长。点主花圃正中的本命花（或底部“花圃”→ **左外连接 · 本命花**，“晚星”，当前是种子） | 镜头轻移到这株花，旅人走过去照料，右侧打开植物档案：阶段、依据、下一步 |
| 0:40 | 档案中点 **问星灯**，输入：`LEFT JOIN 之后把右表条件写在 WHERE 里，为什么结果像内连接？` 发送 | **个性化答疑**：结合当前知识点、目标与资料回答。回答下方列出引用：资料标题、**版本号**、**页码/段落**；“资料 + 通用知识”标签区分依据 |
| 1:00 | 点引用 **资料1**，右侧打开资料温室并高亮被引用的片段；点返回到对话（顶部“对话”） | 引用绑定到不可变的资料版本；旧回答引用旧版本 |
| 1:10 | 提示条：“左外连接 种子 → 嫩芽：新增提问证据” | 成长只来自后端确认的证据，不是聊天次数 |
| 1:20 | 回答下方点 **做练习** → 在《每位学生的本学期选课数》上点 **引导练习开始**。点 **看提示**，故意输入错误答案：`SELECT s.name, COUNT(e.cid) AS n FROM students s LEFT JOIN enrollments e ON e.sid = s.sid WHERE e.term = '2026秋' GROUP BY s.sid, s.name`，**提交** | 答案在独立的只读 SQL 沙箱中执行并与参考结果比对；规则诊断指出“学期条件写在 WHERE”。答错不让花死亡：引导练习 → 生叶 |
| 1:50 | **再练一道** → 选择“每门课程的高分人数（变式）”→ **独立作答开始**，输入：`SELECT c.title, COUNT(e.sid) AS n FROM courses c LEFT JOIN enrollments e ON e.cid = c.cid AND e.term = '2026秋' AND e.score >= 80 GROUP BY c.cid, c.title`，提交 | 没做过的变式、未看提示、答对 → 光点汇入，花瓣展开（只在后端提交成功后播放） |
| 2:15 | 顶部 **历史**：关键词 `LEFT JOIN`，点检索 → 两组问答（今天的，与约 9 天前的预置记录）。再把开始/结束日期都设为今天、知识点选“左外连接”，检索 → 只剩今天这组 | **历史问答梳理**：关键词 + 时间 + 知识点组合，在服务端执行并带本人权限；匹配片段高亮 |
| 2:35 | 点结果卡片 → 回到原会话，**原消息高亮**并保留前后文；在输入框继续问：`那 RIGHT JOIN 也会这样吗？` | 定位原消息并从原位置继续对话 |
| 2:50 | 点顶部“花园”回到花园，再点左前方花圃里的 **条件概率**（开花，来自预置记录） | 同一套结构用于概率统计：提问、资料（PDF 页码）、练习与证据，可跨学科复用 |

## 二、八分钟答辩版

在三分钟版的基础上增加：

| 时间 | 内容 | 材料 |
|---|---|---|
| 3:00 | **需求与范围**：两项必选（个性化答疑、历史检索）与两项推荐（资料整理、薄弱点训练）的对应；P2 增强为班级星系 | `docs/requirements-matrix.md` |
| 3:40 | **E-R 图**：总览中的实体、联系与基数；弱实体“资料版本 / 资料片段 / 题目版本”；“当前状态”是用户—知识点之间带属性的联系 | `docs/er/er-overview.svg`、局部图 2、3 |
| 4:30 | **关系模式与规范化**：① plants / concepts / learning_states 分解（部分依赖 → BCNF，无损连接）；② messages.user_id 的受控冗余与复合外键；③ 引用只存 chunk_id（避免传递依赖与更新异常）；④ learning_states 作为可重算的汇总 | `docs/database-design.md` §4 |
| 5:30 | **大模型辅助设计记录**：初始候选 → 审查 → 修改 → 理由（如合并 state_history 与 growth_events） | `docs/llm-assisted-design.md` |
| 6:00 | **关键 SQL**：历史检索语句（三路候选 + 时区边界 + 知识点 EXISTS）；递归 CTE 先修闭包与防环触发器；互补伙伴匹配 | `docs/sql/core_queries.sql`、`docs/sql/explain-results.md` |
| 6:40 | **事务与一致性**：幂等键与唯一约束；评价在事务外、证据—状态—事件—outbox 在同一事务；故障注入回滚；并发争抢最后一个共学名额 | 现场运行 `npm test`（约 15 秒），或展示 `docs/test-report.md` |
| 7:20 | **班级星系（增强）**：顶部“星系” → 只显示公开的星球；公开意愿 → 可解释的互补伙伴；双人小组名额 1/2 | 界面 |
| 7:45 | **诚实边界**：演示模式不调用模型；检索为词法检索；未做用户实验；阶段不是掌握度测量 | `README.md` 已知限制 |

## 三、约 30 秒宣传录屏流程

建议录屏分辨率 1920×1080，窗口全屏，系统未开启“减少动态效果”。

| 秒 | 画面 | 对应真实功能 |
|---|---|---|
| 0–5 | 打开首页：星空中远处的小星球缓慢靠近，出现长椅、路灯和一小块空花圃 | 开场（未登录首页） |
| 5–10 | 文案“如果你有一颗自己的星球，你想在上面种下什么？”→ 点“体验新旅人开场” | 新账号（真实写库） |
| 10–15 | 输入目标“弄懂 LEFT JOIN 与 WHERE 对查询结果的影响”→ 确认知识点 → 选“鸢尾 · 雾紫”，命名“小雾”→ 种下 | 开场事务：星球、目标、路线、植物、本命花 |
| 15–20 | 问星灯同一个 LEFT JOIN 问题，回答带资料引用；种子发芽 | 个性化答疑 + 提问证据 |
| 20–26 | 做变式题并独立答对：光点汇入，花瓣展开 | 独立变式验证（后端提交后播放） |
| 26–30 | 打开历史，输入 LEFT JOIN，点结果回到最初的问题（高亮） | 历史检索 + 定位原消息 |

注意：新旅人账号的植物从种子开始，需依次完成“提问 → 引导练习 → 独立变式”才会开花；若只想录开花片段，可直接用演示账号的“左外连接”，在 1:20–2:15 的步骤录制。
